# Guidance that names a moment survives; guidance that names a stance erodes

*What makes an instance work has to ride the front-door composition and fire at named acts — a disposition asked for across time has no moment to attach to, so it attaches to all of them equally, which is to say none.*

## The claim

A corpus accumulates hard-won working knowledge: how to read here, what to check before claiming, which move is a known trap. The natural place to put it is a document describing how a good agent behaves here. That form fails in a specific, repeatable way, and the failure is not weak will.

**The mechanism.** An agent's behavior at any instant is selected from the options that are live *at that instant*. A directive naming a stance — *be careful about X*, *consider doing Y* — can only take effect if a decision point occurs where the option is already on the menu. When the default rhythm never produces that decision point, the directive is read, agreed with, and never fires; the agent experiences neither refusal nor lapse, because from the inside no choice was made. A directive naming an **act** — *before writing "recorded," verify a tool fired*; *when you load a read with more than one path, that is the decision point* — interposes at a moment that actually occurs, which is why it survives contact with work.

The predictive form: for any convention a corpus proposes to write down, ask **which act it fires at**. If the answer is "throughout," the convention will erode invisibly, and its erosion will not be detectable from the fact that everyone agrees with it.

**Why this is a front-door question rather than a documentation one.** Activation is not the same as availability. Material that is somewhere reachable is inert; material composed into what an instance loads at the start of every session is what shapes the run. The corollary is uncomfortable: knowledge accumulated in memories, per-record notes, and side files is *not activated* however true it is, and moving it to the front door is a real act with a real cost — front doors are the one surface where every session pays for every line. That cost is the reason the material has to be shaped as triggers rather than as prose: a trigger earns its line by firing.

**Two shapes are live for the same instrument, and choosing between them is the open design question.** A front-door file can carry pre-action blocks — *before doing X, read Y* — as prose at the door. Or the trigger can be a typed field on the record itself, so that the record carrying the knowledge also carries the moment it applies. The first activates unconditionally and costs every session; the second is precise and only fires if the record is reached. Nothing adjudicates which, and instances have gone both ways.

**Related but distinct: the activation-by-restatement effect.** Content an instance already holds can be restated at the point of use to make it operative there — the same words in a new context are not redundant, because activation is contextual rather than informational. This is real enough to be worth naming, and unmeasured enough that it should not be leaned on: it is exactly the kind of claim whose plausibility invites unlimited restatement, which is the failure mode a front door cannot afford.

## Strength & grounds

**Heuristic, with two independent incidents and two live implementations.** The mechanism's founding case is recorded in `~/src/arch/asf/doc/sop/audit.sop/de-novo.sop.md` §4.4 (read first-hand 2026-08-06): the agent that co-wrote the file's serial-reading rule batched five records into one read within minutes, and its own account is that *"the 'consider' never fired as a decision point"* — the option was not on the menu, so no choice was experienced. The file's own correction is the act-shaped restatement: the multi-path read call is itself the decision point. The two shapes are both live — prose pre-action blocks in a project front door, typed `|before-acting` / `|on-reading` trigger fields on records in the comproprium corpus (registered as TODO entry N23, not re-verified here). The activation-by-restatement effect is asserted in that same SOP §1.1 (*"reading it as part of these audit instructions activates it more strongly in this specific context"*) and is untested.

**The second incident is the sharper one, because it was measured rather than noticed, and it supplies the controlled comparison the first lacks.** A corpus elsewhere in the estate ran a set of checks written as stances. They fired on schedule through a morning and returned clean while the agent under them produced exactly what they watched for; the one that did fire was read and answered *"yes, but it is warranted."* The same list rewritten as moments-with-acts returned three real findings within a minute. Same content, same reader, same session, opposite yield — which is as close to a controlled test of stance-versus-moment as the estate has. The corpus also recorded that it caught the defect class on the author of the very segment stating it, three times in one evening, by an instance already corrected twice.

That specimen is **inherited at a stated remove**: it is registered in this project's queue as a first-hand-verified entry (V10, `ver-act-not-intention`) from a strand reserved for a joint review, and it was not re-read at its source while drafting this segment. Its register is preserved rather than upgraded.

Two incidents from one estate, one of them self-reported and one measured on its own author, is not a rate. What raises the claim's standing is that the second supplies a before/after on the same material, which the first cannot; what would raise it further is a single instance outside this estate.
