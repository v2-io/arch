# Two terminology stores, side by side

*The estate's two live vocabulary substores — one directory-as-table with append-only decision events, one single-file dictionary with a graveyard — measured and compared, as the material behind [[terminology-substore]].*

## The two instances

Read from the live trees on 2026-08-06.

| | `asf/terminology/` | `vivarium/LEXICON.udon` |
|---|---|---|
| Storage form | one file per term under `entries/<slug>.md` | one file, 106 `\|term[…]` elements |
| Size | **176** entries | **106** terms (74 settled · 9 carved · 23 open) |
| Decision history | `decisions/<slug>/<ts>-<decider>-<action>.md`, append-only — **149** directories, **160** events | prose provenance in the file's own meta block; carve-blocks relocated to the council ledger 2026-07-13 |
| Reader-facing view | `LEXICON.md` (384 lines), generated by `bin/term render`, hand-edits overwritten | the file itself is the reader-facing artifact |
| Retired terms | entry files persist; supersession recorded as a decision event | a separate graveyard, `.archive/SUPERSEDED.md` (94 lines) — *"do not use this anymore, use that"* |
| Status vocabulary | on the entry frontmatter | `settled` · `carved` · `open` (needs the steward's decision) |
| Concurrency | per-entry files; `safe_write` (temp + fsync + atomic rename); same-key writes deliberately unserialized | single file; ordinary read-modify-write |

## What each one got that the other did not

**The asf store's distinctive move is that a naming decision is an event, not a field.** Its own README states the reason: *"Mutable status fields lose that history (and lose it silently when overwritten). Append-only files preserve it."* Event filenames carry a UTC timestamp, the decider, and the action, so two agents recording decisions on the same term never collide — the write-safety property falls out of the naming scheme rather than being enforced. A sampled event is six frontmatter lines plus one line of reason.

Two further mechanisms sit there and are not obviously terminology-specific:

- **Permissive extractor, strict linter.** `render` always emits and marks missing required fields `(missing)`; `lint` is the only place schema problems surface. The stated effect is that the generated view shows the current state of the world even when entries are mid-edit.
- **Vocabulary may land before the tooling knows it.** `bin/term decide` warns on an unrecognised action but does not block, explicitly *"so new event-type vocabulary can land before the CLI knows about it."*

**The vivarium store's distinctive move is that the dictionary states present truth only, and says so with a mechanism.** History does not live in the lexicon; a retired term goes to the graveyard index. But two fields are deliberately *kept* in the live entry — `|not` (what this is not, what not to call it) and `|confused` (what it is easily mistaken for, and how to tell) — on the stated ground that these are **present-tense disambiguation against a live neighbour, not history**. That is a sharper cut than "history goes elsewhere" usually gets, and it is a distinction a purely mechanical present-truth rule would delete.

It also carries an explicit **register convention** — Greek for the law-article machinery, Latin for the world-governance layer, plain English for lived concepts — with the instruction that a proposal crossing registers should notice it is doing so. And a stated motivation worth keeping, from the steward: names are how a project stops re-arguing decisions that were already made.

## One live tension, recorded as-is

The vivarium lexicon's section numbers §1–§8 are **frozen because external documents cite them** — the file's own meta block says so. That is a positional reference surviving as an accepted liability inside a corpus whose own format law elsewhere forbids path- and position-anchored references ([[identities-over-locations]]). Nobody has resolved it; the freeze is the workaround. Meanwhile the same corpus's cross-member reference scheme in its FORMAT does use identity form, including a dedicated term namespace (`#asf/term/<slug>`) — so both designs are live in one corpus, in different layers, one of them declared frozen.

## Method & scope

`ls | wc -l` for entry and decision counts; `find -type f` for the event count; `grep -cE` on the udon sigil for term count and on `:status` for the split; `wc -l` for file sizes. Both READMEs and the vivarium meta block read in full; quotations verbatim. The asf `bin/term` implementation was not read — the atomicity contract and the permissive/strict split are quoted from the store's README, which describes the code rather than being it.

Two instances in one estate. Neither has been measured for the thing that would matter most — whether the vocabulary is actually *used* consistently in the prose it governs. Both stores can be perfectly maintained and entirely ignored, and nothing here would show it.

## Working Notes

- The uncounted third instance: comproprium ports ASF's conventions by reference and has no store of its own; relata's alias index is a different mechanism for a neighbouring problem (rename survival, registered as N1) and was not compared here.
- The measurement owed: term-usage conformance in governed prose. A `grep` for each `deprecated`/superseded headword across the live tree is the cheap version and would immediately price the graveyard's usefulness.
- Not established and easy to assume: that the 160 decision events are *read*. Their existence is verified; their consumption is not.
