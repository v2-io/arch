## 0. The one-paragraph version

Two projects, built with no shared method, turn out to be two halves of one system. **live_docs** (Samuel Wecker, ~10 weeks, shipping) is a knowledge store for coding agents: atomic typed Markdown docs, an explicit dependency graph, cascade-on-change, membrane-gated ingestion, and — its crown — a running accountability mechanism (session write-ahead logs, blocking close-gates, human-signed reviews, drift detectors) plus a failure-metabolism for its agent procedures (per-skill ledgers with failure classes and regression anchors). **Verisectorium** (Joseph's estate: a theory instance plus deployed instances in vivarium, aspectus, udon-references, asf, and others) is the same class of object taken to first principles: what a record *is*, how its epistemic state is warranted rather than asserted, how truth accumulates across 100% agent turnover — carried today in prose discipline and hand-maintained ledgers, with its mechanization deliberately deferred. The blunt asymmetry — as first drafted: *live_docs is mechanism without epistemology; verisectorium is epistemology without mechanism*. **Corrected same-session after a wider instance sample:** the estate has substantial mechanism — vivarium's cryptographically-sealed orientation gate (`prove-me`/`orient-check`, with compaction-generation expiry), `orient-rank`'s six-factor study ranking, asf's `lint-outline` (outline-order vs `depends:` DAG, cross-component refs, orphans, stage-field-vs-row consistency) and its monograph build pipeline — so the true asymmetry is **bespoke per-instance mechanism vs. shared portable mechanism**: every estate instrument is locally excellent and none transfers without a human carrying it, while live_docs is one engine that installs anywhere and carries thin semantics. Each side has independently produced what the other is missing. live_docs' session WAL is the only running approximation of verisectorium's central unbuilt object (the append-only trail that statuses should be computed from), and verisectorium's dimension/authority/ceiling vocabulary is the answer to every ache live_docs' own wishlist records about its fused status fields. The join is unusually short, and §7 walks it in detail.

## 1. live_docs, from zero

### 1.1 The problem it attacks

Documentation rots: it is stale within hours and misleading within weeks, so teams stop trusting it, and the *reasoning* behind a system — why it is shaped this way, what was decided and rejected, what is aspirational versus real — survives only in heads and chat logs. Coding agents inherit the blind spot. live_docs' stated bet: don't regenerate docs from code (that recovers the *what* and loses the *why*), and don't lean on human discipline (it fades) — keep the knowledge itself **living**: atomic single-responsibility docs, an explicit dependency graph that makes any change's blast radius computable, and a cascade that surgically regenerates affected docs when something moves.

### 1.2 The five commitments (its own framing, condensed)

1. **Docs lead; code aligns.** Docs are the source of truth for intent; a doc/code mismatch is a signal, not an impossibility.
2. **The why, not the what.** Capture only what code cannot re-derive.
3. **Accuracy, not access.** The hard job is write-time truth-keeping, not retrieval; RAG/MCP are someone else's layer.
4. **Living, not snapshotted.** Cascade rewrites stale docs to current truth — never flag-and-forget.
5. **Revisable, not just enforced.** Every decision records its why and dependencies so it can be safely changed later.

### 1.3 The machinery

- **Docs**: one responsibility per file; opaque timestamp id (id = filename, permanent); frontmatter with `title` / `label` / `summary` (three descriptors with distinct jobs), `type` (principle | goal | decision | constraint | requirement | use-case | guide | component | reference), `status` (living | target | deprecated | reference), `level` (incidental | trial | preference | requirement), and typed edges.
- **Two graphs**: `belongs_to` — an acyclic navigational hierarchy whose interior nodes are "signposts" (`ldoc map` prints them as the store's front page); and `requires`/`relates` — a cyclic dependency web plus see-also. `provenance` and `superseded_by` ride separately. Only `requires`/`belongs_to` cascade; `relates`/`provenance` never do.
- **Cascade** (`cascade-check` skill): two strict passes — a read-only BFS collecting a verdict per reachable neighbor (*inconsequential* | *cascade* | *incompatible* | *context-request*), then one batch write pass. Frozen docs (deprecated/reference) are never rewritten — conflicts with them surface as `incompatible`. A "restated-ownership repair" collapses copied enumerations to a link to the owning doc rather than syncing the copy. A wide-cascade warning (>3 docs from one edit) routes to maintenance as a single-responsibility smell.
- **Membrane**: inbox (instant capture, zero ceremony) → promote → raw tier (immutable archive, *outside* the graph) → `ingest-reference` (mandatory decomposition into atomic docs — "a blob ingested as a single doc is a liability"), with a volume-triggered sharding pre-pass for oversized clippings.
- **Accountability**: every mutation routes through one choke-point that double-writes a per-doc history entry *and* a line in the open session's write-ahead log (WAL). `ldoc session close` **blocks** until every revision-class change carries an author-supplied why, then folds the WAL into exactly one review file. Reviews are post-hoc, non-gating, human-signed (`ldoc review sign`). Ingest state is **hybrid**: an explicit flag cross-checked against graph evidence, with disagreement surfaced as `⚠ DRIFT` rather than resolved silently.
- **Division of labor**: the `ldoc` CLI is deliberately *dumb* (Python 3 stdlib-only, zero dependencies — a stated stance) — it writes what it is told and validates references; all judgment lives in ~24 prose "skills" (agent procedures) with shared single-owner discipline files (`_shared/doc-style.md`, `status-living-vs-target.md`, …) cited rather than restated.
- **Self-hosting**: the `kb/` under the repo is live_docs' own design documentation, maintained with its own tools — 235 docs, ~800 edges, `validate` at 0 errors, 67 review episodes over ten weeks.

### 1.4 Condition (measured, 2026-08-29)

Code quality is good and honest about its debts (a frontmatter-splicing function carries a comment naming its own fragility and the right fix; `ldoc new` rolls back the doc file if the history write fails so no orphan can exist invisible to reviews). Known soft spots: three-plus ad-hoc line-scanning frontmatter readers (the one structural risk I'd prioritize — a shared parse/emit layer, which the author has already named); no test suite (principled but increasingly expensive now that WAL/close/merge logic carries invariants); timestamp ids that collide under concurrent agents (wishlisted); AGENTS.md drifted from the code on the `created` field (the operating manual lags a migration — a pointed irony in a drift-fighting tool); 55 validate warnings of one class (body wikilinks not materialized as edges — the designed `garden-densify` pass simply hasn't run); and several docs with the type baked into the title so displays double it ("Component: Component: …") — agentic formatting drift its own `garden-refine` phase exists to catch.

## 2. Verisectorium, from zero

### 2.1 What it is

"Verisectorium" names a pattern that kept re-establishing itself across Joseph's estate — **outline + segments**: stable atoms (one claim/definition/norm/observation per file; the slug is the identity, never position or number), an outline as a cheap authored *view* carrying order and per-row state, and epistemic state carried honestly per atom — because it is a solution to **100% agentic turnover in complex living creation projects**: every reader arrives with total context turnover, so the collection is the sole carrier of what it knows, comprehension cost compounds per reader while authoring cost is paid once, and therefore every record must say *in itself* how strongly it is held and why. The theory instance (`~/src/arch/firmatum/verisectorium/`) exists to understand the pattern from first principles and to distill a deployment template; the deployed instances came first and remain the evidence base.

### 2.2 The theory's core (RC1 — register: proposed, none ratified)

The current epistemic core, in one paragraph of its own words: "A record's kind is individuated by **how it fails and what repairs it**, and adjudicated on its kind's **epistemic dimensions** — the questions its soundness consists in; its state is **the trail of securing acts performed on it, with every status a computation over that trail — never a hand-set word**." Around that sit: ~eight dimension namespaces (Evidence — is it true?; Backing — who is accountable, who consulted, on what grounds, what reopens it?; Fidelity — faithful to what happened?; Efficacy, Comprehension, Conviction, Freshness, Disposition — honestly marked as three matured and five candidates, the set open by construction); a **substitution law** ("no dimension's value ever substitutes for another's" — *ruled* does not make it true, endorsement cannot move the firing ladder, a beautiful explanation is not support — every entry a failure already paid for); the **coherence default** (agreement between lines adds weight only to the degree they can be shown not to share descent, the default being that they do — same-author restatement is coherence, ~zero marginal weight); the **commitment law** (a check corroborates only if its pass-criterion was committed before contact with the outcome); typed edges with per-kind composability (`supports` never propagates strength transitively; `seeded-by` is the one deliberately transitive edge, because descent genuinely flows; **rebut** — attacks a conclusion, hard cascade — split from **undercut** — weakens support, conclusion possibly still true, soft re-pricing); ceilings ("Max") assignable per claim-kind before work, naming the evidence-action that would raise them; certification bounded by grader independence, never effort, decaying with its warrant; and the mirror of overclaiming, **under-recording** — securing work done but unrecorded is "just as dishonest as an unwarranted lift," because it corrupts the semantics of absence (a reader can no longer tell *unrun* from *ran-and-unrecorded* from *declined-to-lift*), so deliberate non-lifts are themselves recorded as decline-events, and the deep remedy is economic: make stating the act *be* recording it.

Nine "organs" organize the structural side (Corpus, Vocabulary, Veritas, Adjudication, Flux, Views, Experiential Interface, Stewardship Interface, Norms), crossed with a process layer of clocked flows. Load-bearing pieces that recur below: **flags-not-gates** (independent resettable check-flags per atom instead of promotion ladders — "a ladder that only promotes accumulates falsehood"; updating a well-verified atom must feel like advancement, not regression); the **influx membrane** (nothing writes the population directly; drop → adjudicate → land, with typed outcomes distinguishing *rejected* / *needs-review* / *skipped*); the **delete-test** ("assume the item disappears entirely: is every piece of its information landed or truly disposable?" — a register *about* remainders is not the remainders landed); **dispatch-compounds** (residue on live search surfaces bills every future reader and bifurcates the system toward a clean or a residue attractor — half-dispatched "false nuggets" are worse than noise because they *reward* widened search); and **outline-as-view** (multiple coexisting views over shared atoms; trimming = view membership, never atom-editing).

## 3. Field evidence: live_docs in production (the part neither README shows)

Because live_docs is dogfooded on its own repo and used against at least one production consumer store (Mountain Biometrics — visible only through specimens its skill ledgers quote back), its inner layers are a ten-week field journal. Mining them (git history with bodies; all six skill ledgers; reviews; drift flags; doc histories; `git-heat`) yields the strongest material in this whole comparison.

### 3.1 The skill ledgers — a working failure-metabolism

Every skill fix follows one disciplined shape: **Failure** (the actual production specimen, quoted) → **Class** (A: information was missing entirely; B: the skill's own text *permitted* the bad reading — with the permitting sentence quoted; C: user-confirmed promotion to invariant) → **Diff** ("placed at the point of highest leverage — immediately after the phrase that most directly permits the bad reading — rather than touching every downstream phrase") → **Declined this pass** (with reasons and revisit conditions) → **Regression answers** (every known-good property re-verified per edit — "diff-verified (confirming untouched sections are byte-identical) rather than execution-verified. Flagging this rather than overstating confidence") → **Ping-pong check** (explicit anti-oscillation audit against prior ledger entries). The author even caught eval contamination in his own test method: rewrite-executors are now "given ONLY the skill files — no failure examples or coaching in the prompt, which contaminated the v1 test." This is verisectorium's sop-influx + regression-guard + de-novo-testing disciplines, independently reinvented, and in mechanical rigor arguably ahead of most estate instances.

### 3.2 The failure catalog — estate twins, found independently at production cost

1. **Authority inversion** (2026-08-12): a 19-doc reconcile run recorded an implementer's own conveniences at `level: preference/requirement` while "user-stated claims were recorded weak/agent-attributed… **inverting the record**." The estate's speaking-in-the-principal's-voice / authority-laundering failure, discovered from scratch — with a structural diagnosis: nothing anywhere checked a new doc's claim against a higher-`level` existing doc (Class A: "the level-collision check had no home anywhere in the pipeline").
2. **Root-over-decision** (2026-07-23, C-invariant): agents kept producing decision inventories; the correction — "live_docs is a **why-lens, not an ADR dump**; decisions are useful for modeling relations but the nonrecoverable roots are the prize." The why-web doctrine, verbatim in spirit.
3. **The register war** (2026-08-24 — three ledger iterations in one day): doc prose kept coming out oracular ("gold that guesses permanently mislays the finish line"). Banning the *diction* produced manifesto-shaped rewrites anyway; banning the *shapes* (epigrams, antithesis cadence, punchlines, maxim headings — each with a mechanical tell) still left pomposity; the root was **stance**: the docs were written as *arguments* where documentation should *describe* who does what. Buried gem: "the argument register also **concealed a factual error… through synthesis, two style passes, and two close readings**" — flourish-signals-misdirection with its mechanism stated (argument register makes claims uncheckable). A same-day amendment self-caught a second estate law: the fix had narrated the store's own failure history into the shared skill file — "authoring-process material belongs here in the ledger, not the skill text" (the no-fourth-wall rule).
4. **Inline-substitution** (2026-08-10): an agent performed a sub-skill inline instead of invoking it — and therefore **never read the four shared discipline files reachable only from that skill**. 14 malformed docs; "the store validated clean throughout"; "the same feedback they give every agent on its first ldoc writes." Three general laws in one specimen: green structural validation ≠ good content (verification vs validation, lived); **the reachability graph of skill files determines what agents actually read**; and the Class-B root was *cadence* — steps 2–4 said "Run /skill" while step 5's contrastive phrasing read as permission to inline.
5. **Conservative punting** (2026-08-25): an agent found a doc contradicted by settled authority and handed it back as "out of scope, worth a separate look." Owner's ruling: "nobody should have needed to ask." Repair by definition-sharpening: *unresolved* means genuinely contested authority, nothing else.
6. **Pause-gate rubber-stamping** (2026-07-23): the skill paused on impact-*size* and asked yes/no to do exactly what the user requested. Fix: "the gate is for conflicts / unintended side-effects, not a permission slip for expected work."
7. Plus: `status: target` overuse (everything pre-implementation stamped aspirational → a shared deferral test: default `living`; `target` only for initiative-level unbuilt direction or explicit deferral); answer-shaped labels ("Presence Is The Ceiling" rejected — a label that states the conclusion is wrong even when every word came from the session); domain-echoes-scope mis-tagging with the mechanical CLI remedy *noted and honestly deferred*.

### 3.3 Store-health signals

- **Hot-file churn is healthy**: the highest-history doc (18 entries) is the root Foundational Principles signpost — expected — and its trail is genuine intellectual history, including removing a generated member-enumeration in favor of derived membership (singular ownership applied to itself) and a retype with reasoning recorded.
- **The drift detector fired and told the truth — but nothing drains it**: 29 `⚠ DRIFT` flags, all one retroactive class (docs reference a raw whose flag predates the flag mechanism), standing unreconciled for two months. A detector without a clocked drain.
- **The human loop is real and visibly silting**: 45 of 67 reviews signed (by Samuel personally), signing in batches with up to 6-day lag, 22 unsigned clustering mid-July. Non-gating-by-design means the residue accumulates silently — and the wishlist already senses it ("really emphasize that the review process… shouldn't ever be skipped").
- **Schema migrations were handled honestly**: convention change → whole-corpus sweep in the same commit ("Re-summarized all 76 docs, avg now ~41 words"); `state`→`status` folded with legacy support then removed. The dumb-mutator CLI is what made sweeps cheap.
- **Heat migration** (git-heat, measured): over the whole history, heat splits between the CLI engine and the skill layer with the KB warm only at its signposts. At a short half-life, **the code is cold and 100% of recent heat is in skill prose and its ledgers** — the four hottest files in the repo are regression-notes and ledgers. Two readings, both true: the "dumb mutator, judgment in skills" thesis working as designed (once the mutator is right, all remaining failure surface *is* the skill layer, being paid down against production specimens); and the estate's caught-disciplines-become-mechanisms signal firing (prose-governed judgment keeps needing re-fixing — three register iterations in one day; the same first-agent feedback "every time" — so the recurring classes have earned promotion to mechanical checks).

## 4. The convergences — and how much they are worth

The two systems share, arrived at with no shared method: atomic docs under stable position-free identity; a hard/soft edge split with only the hard edges cascading and provenance excluded from cascade in both; an entry membrane with an immutable raw tier *outside* the graph in both; frozen snapshots never rewritten (conflicts surfaced instead); deprecation-with-teeth (Correction + supersession edge mandatory ↔ typed supersession + no-go landing); overload smells (wide-cascade / hot-file ↔ single-responsibility at adjudication grain); copy-collapse (restated-ownership repair ↔ defer-don't-fork / singular ownership); post-hoc non-gating human review (signed reviews ↔ steward valve, flags-not-gates); a judgment/mechanism split ("dumb mutator + skills" ↔ "logogenic proposes, deterministic disposes"); and a feedback inbox as the amendment channel (live_docs' inbox ↔ sop influx ↔ aspectus's inbox.md — the same organ grown three-plus times).

**The honest weight** (verisectorium's own coherence default applied to this report): the authors are brothers, and shared conversations or shared reading cannot be excluded — this is not clean descent-cut corroboration, and nobody should cite it as such without asking Samuel what seeded live_docs. But the *strongest* convergence evidence needs less independence than the design-level parallels: §3.2's failure catalog emerged from **agents in production**, not from either estate's writings — authority inflation, register drift, punting, permission-theater, why-loss surfaced on a months-scale lag in both systems and were fixed by the same class of remedy (shared single-owner definitions, mechanical checks, honest weak-states, register discipline). The failures' descent is thin; the problem itself keeps dictating the shape of the solution. That is the report's strongest single finding.

## 5. What live_docs does really well

1. **It runs.** A working CLI, ~24 skills refined against ledgered failures, sessions/reviews/viewer/multi-repo stores/install story/plugin packaging. Verisectorium's own Part IV concedes the deployment components exist "in zero existing deployments" estate-side; here they exist.
2. **The WAL/close-gate/review pipeline** — the only running approximation, anywhere in view, of the trail that RC1's epistemology is built on. Every mutation through one choke-point; sessions that cannot close with unexplained revisions; per-doc history *materialized from* the WAL at close (the projection direction RC1 wants, already pointing the right way); reviews carrying the raw WAL archived in a comment block.
3. **Instrument honesty in the mechanism**: the hybrid ingest-state check (flag × graph evidence → `⚠ DRIFT`) is verisectorium's never-trust-a-status-label law implemented; the review-with-empty-touched warning, the `ldoc new` rollback-on-failed-history, the fail-loud-never-prompt posture — all the same instinct.
4. **The skill-ledger methodology** (§3.1) — portable as-is, and in some respects tighter than estate practice: the failure-class taxonomy, regression-answers-per-edit, the ping-pong check, and the uncoached-executor test protocol are each worth adopting into estate sop-influx practice verbatim.
5. **Shared-file discipline architecture**: one owner file per cross-cutting rule (`status-living-vs-target.md`, `doc-style.md`, `label-title-summary.md`), cited from every writer — defer-don't-fork realized for skill prose, and the heat map shows fixes landing once and radiating.
6. **Capture ergonomics**: the inbox's zero-ceremony drop (no frontmatter, no thinking) with deliberate gates behind it is a better *capture* story than any estate instance currently offers; provenance flags (`--origin`, `--medium`, `--authored-at`) captured losslessly at gate 0.
7. **The viewer** — a self-contained HTML projection of the store (hierarchy reader, edge-aware neighbor graph, review queue) that no estate instance has an equivalent of.
8. **Honest self-knowledge**: WISH.md and the ledgers show the author repeatedly identifying his own system's weak joints (status/level confusion, review non-skippability, id collisions, reference immutability) before any external review did. Most of §6's transplants land on soil he has already tilled.

## 6. What verisectorium does really well — and what each should take from the other

1. **The epistemology.** live_docs' `status` and `level` are hand-set scalars — exactly RC1's named historical failure ("a hand-set word can lie; a status projected from a trail of recorded acts can be checked by anyone, forever") — and each fuses several independently-movable values (status: temporal claim + lifecycle + doc-class; level: groundedness + authority). RC1's fusion tell (a ladder whose values are cross-products of independently-movable parts) fires on both, and vivarium demonstrates the un-fused form is *practical*, not just theoretical: status/Max/stage as three fields, maintained for months across ~117 segments. Samuel's wishlist ("better clarification between these; stricter/better assignment") is the felt symptom; the dimension split is the structural answer.
2. **Decision authority.** The estate's decided-by vocabulary is three editions deep because "the weight of a decision is who stood behind it and how." A live_docs `decision` doc cannot say who decided, cannot say `defacto` or `transition` or `lead` or `wish`, and its skills' worst production failure (§3.2 #1) was precisely an authority inversion. Transplant: a `decided_by` field (minimally `steward | ratified | proposed | defacto`) on decision-type docs, plus the weak statuses — cheap schema, scar-earned doctrine riding along as skill prose ("do not inflate — this is the one field where an error is not merely wrong").
3. **Kind derivation over fixed taxonomy.** Three estate instances derived three different type-sets by asking, per record kind, "what should go wrong with this, and what should adjudicate and repair it?" — and lean on the distinctions constantly (measured observation split from unratified design "so the numbers survive the design's death"). live_docs ships nine fixed types where `decision` must impersonate ratified-law, working-choice, and measured-finding at once. Its wishlist already wants configurable types; RC1's founding questions (Q0–Q8: standing, speech-act, failure, instrument, dimensions, movers, ceiling, grain/edges, certification) are the how.
4. **Rebut/undercut in cascade.** live_docs' cascade treats "upstream refuted" and "upstream weakened" identically; they are not — one demands hard cascade, the other degrades support without attacking the conclusion. A fifth verdict (`undercut`: re-secure question minted, no rewrite) would cut cascade's rewrite volume and, with it, the fluent-regeneration exposure of having an agent rewrite prose "to current truth" on every soft change.
5. **Coherence/descent awareness.** Nothing in live_docs asks whether two agreeing docs share descent, or whether a check's criterion was committed before its outcome was seen. For a store maintained by agents ingesting agent output, that is the next failure class it will meet. Its `provenance` edge is one semantic step from `seeded-by`; `map-concepts-to-docs` treating same-provenance agreement as dedup signal rather than corroboration is the cheap first move.
6. **Typed absence.** Vivarium's outline carries `#gap` rows — "a segment belongs here and does not exist yet" as first-class store content. live_docs cannot currently distinguish a known gap from assumed coverage; known gaps are routable, assumed knowledge detonates.
7. **Orientation.** "The same feedback they give every agent on its first ldoc writes" is a named recurring cost with a named estate solution: an orientation gate (doctrina before work; verifiable, scoped to context lifetime) plus a professio. live_docs has no orientation layer at all; verisectorium's is liftable nearly as-is, and it directly attacks the reachability failure of §3.2 #4 (an oriented agent has read the shared discipline files before any pipeline runs).

**And in the other direction** — what the estate should take from live_docs, beyond the headline WAL (see §7): the ledger methodology and its uncoached-executor test protocol (§3.1); the reachability audit as a general law ("any discipline file referenced from only one place in a pipeline is invisible to every agent that shortcuts that place" — worth auditing estate SOP stores for); the zero-ceremony capture gate; the reviews-with-archived-WAL shape as the certification record; the viewer as the missing Views-organ tooling (pointing it at a verisectorium corpus is roughly a weekend adapter — the data models are that close); and the mechanization of graph hygiene that instances currently hand-pay in Working Notes (reverse-edge indexes, supersession bookkeeping, restated-ownership detection, orphan lists, dangling-ref validation). The most productive corpus in the estate (vivarium) spends real per-session effort on "dual-home demote," "ice once this lands," residue maps, and hand-maintained `depends:` lists — the instance-building-competes-with-instance-filling tax, being paid in exactly the coin `ldoc reindex`/`validate`/`link` mint for free.

### 7.2 Step one, concretely: trail-ify the WAL

The single highest-leverage move, because it converts the running system into the theory's substrate without breaking anything:

1. **Extend the WAL event** with three optional fields: `criterion` (what this act was checked against), `commitment` (`pre | post`), `era` (a store-registry key for anything measured). Existing entries remain valid — absence means "unrecorded," which the under-recording economics already prices.
2. **Add securing-act verbs** so stating the act records it (RC1's economic remedy, and the direction ldoc's `--note`-on-the-mutating-command design already leans): e.g. `ldoc check <ref> --criterion "..." --outcome pass|fail`, `ldoc decline-lift <ref> --because "..."` (the decline-event that keeps absence meaning *unrun*), `ldoc decide <ref> --by steward|ratified|proposed|defacto --grounds "..." --reopen-when "..."`.
3. **Compute status as a declared projection.** Keep `status:` in frontmatter for greppability, but make `validate` recompute it from the trail and flag divergence: the **label-lie check** — a status no event supports, or one surviving events that invalidated it. This is a check no amount of skill prose can run reliably, and it is exactly the class of drift the store's own August history exhibits (docs stamped `target`/`living`/`preference` by generation-time vibes).
4. **Certification semantics on reviews**: record grader-independence mechanically (signer ≠ WAL session author — both already in the file); decay a review's standing when a touched doc is subsequently edited (reset-on-edit — flags-not-gates' one mechanism, and the same machinery closes live_docs' silting problem by making *unsigned + decayed* a queryable, naggable surface).

Worked micro-example of the payoff, using §3.2 #1's real failure: under the current system, the implementer-convenience doc carried `level: preference` and nothing could object. Under the trail form, `level` (better: `decision/accountability` + `decision/grounding`) is a projection: no `decide --by steward` event exists, so the projection computes `proposed`/`incidental` **regardless of what generation-time enthusiasm wrote**, and the recorded inversion (user-stated claims weak, agent convenience strong) becomes mechanically impossible rather than ledger-corrected after the fact. That one failure, prevented structurally, pays for the whole migration.

### 7.3 Step two: split the fused enums (minimal version)

Not eight dimensions on day one. The minimal honest cut, informed by what the instances actually use daily:

- `status` → **strength** (how strongly held: e.g. `proposed | supported | settled`, projections eventually) × **lifecycle** (`current | deprecated | reference`) × keep `target` as what it really is: a **Conviction** marker ("committed, not yet borne out") with the shared deferral test already written.
- `level` → **grounding** (evidence-based) × **authority** (`decided_by`: the seven-value set or a starter subset). The existing skill-ledger rules ("convenience → incidental regardless of build quality; inherited force takes the standing requirement's level") become one projection rule instead of four prose bullets across three skills.
- Add the weak statuses the estate's decision organ earned: `defacto`, `transition`, `lead`, `wish`, `deferred`. Each is an honest state agents currently resolve by silence or overclaim.

### 7.4 Step three: verdict and edge upgrades

- **cascade-check gains `undercut`** (fifth verdict): upstream weakened-not-refuted → dependents' computed strength drops, a re-secure question is minted *only* when the drop crosses a serving threshold, and **no prose is rewritten**. Immediate effects: less rewrite volume, less fluent-regeneration risk, and the wide-cascade smell stops firing on soft changes.
- **`provenance` grows seeded-by semantics** for doc-to-doc descent (keep raw-provenance as-is), and `map-concepts-to-docs` treats same-descent agreement as restatement (dedup signal, ~zero corroboration weight). One sentence in the skill + one edge nuance.
- **`#gap` docs**: a `type: gap` (or a `status`) that `map` shows, `validate` exempts from body requirements, and `garden-hierarchy` homes — typed absence, so a store can say "known unknown here."

### 7.5 Step four: promote the caught disciplines to mechanism

The heat map's instruction (§3.3), all three already named in live_docs' own ledgers as deferred notes: **level-collision check** in `validate` (a new doc contradicting a higher-authority doc — the Class-A gap of 2026-08-12); **domain-echoes-ancestor-scope warning** in `ldoc new`; **title/label lint** (type-prefix baked into title; answer-shaped labels via the pull-quote test the register war produced). Plus one from this review: the summary-length warning exists — add the two data-drift lints observed live (doubled type prefixes; body wikilinks with no edge, which currently accounts for essentially all 55 standing warnings and wants `garden-densify` on a trigger).

### 7.6 Step five: give the queues clocks

Three live_docs surfaces currently accumulate silently: unsigned reviews (22, clustering), DRIFT flags (29, standing two months), and validate warnings (55, one class). Estate law (`claim-clocked-drains`, measured against exactly this failure shape in vivarium's process map): every queue gets a **trigger** (≥1 item = work exists) and a **healing drain** (process one extra per episode ⇒ backlog → 0 by construction). Concretely: `ldoc session close` prints the top of each queue as part of its output (zero new mechanism — the close moment is the one every agent already passes through); `garden` triage reads the same three counters. The review queue additionally wants the decay semantics from §7.2(4) so signing pressure lands where content actually moved.

### 7.7 The other direction: ldoc under estate instances

- **Immediate, zero-risk**: point Samuel's viewer at a verisectorium corpus (segment frontmatter → doc frontmatter is a small adapter); adopt the ledger format (§3.1) into estate sop-influx practice; run the reachability audit over estate SOP stores.
- **Medium**: the verisectorium template's empty `bin/` is shaped like an ldoc skeleton — the instantiation kit's "answer key questions → working instance" wants exactly a store engine with membrane, sessions, reviews, and validate, parameterized by the founding questions' answers (kinds, dimensions, write semantics per kind). ldoc is years of shipped answers to questions the theory has only posed (id minting, ref resolution by id|label|substring, atomic frontmatter mutation, multi-repo store discovery, drift detection). Adopt-and-adjudicate, not adopt-wholesale: the founding questions decide which parts a given instance takes.
- **The decision organ converges from both ends**: udon-references' third-edition thin ledger is drifting toward one-record-per-decision with typed fields — which is an ldoc store with `type: decision` and `decided_by`. Vivarium's O_APPEND single-file discipline solved multi-agent write-safety *within* a file; ldoc's one-doc-per-file solved it by layout (verisectorium's own `form-write-isolation` law: "concurrency by layout, not locks"). The layout answer is the one the theory endorses; the ledger *view* (the greppable one-file projection vivarium's legend wants) becomes a generated view over decision docs — which is also exactly the projection generator vivarium deliberately declined to build bespoke because it "expected to inherit" a principled one.
- **The language horizon** (RC1 file 09, sketch register): a deployment *states* its kinds, dimensions, edges, projections, and gates as declarative rules, and "the model's laws become lint — fusion is checkable, substitution is unrepresentable, hand-set status has no syntax." `.live_docs.toml` plus the store's own config docs is the natural landing surface for the first such declarations; every §7.2–7.5 item is a hand-built instance of a rule that language would express. The migration path from here to there is incremental by construction, because each promoted check is one rule.

## 8. Tensions a union must adjudicate (not paper over)

1. **"Docs lead; code aligns" vs "the store carries adjudicated truth with its warrant."** Reconcilable — intent docs are Conviction-dimension records whose borne-out-ness is *tracked* — but it is a real design act: live_docs today lets a `target` doc assert intent with no machinery ever asking whether the commitment is honored or silently abandoned, which RC1 names as Conviction's dishonesty modes (silent divergence; silent abandonment; the imaginary demand). Vivarium's version ("compliance debt, named, per clause") is the worked middle.
2. **Cascade-regenerates vs projections-recompute.** Where a dependent doc *restates* content, live_docs must rewrite prose (with the restated-ownership repair shrinking that surface over time); where state is computed, verisectorium's re-pricing needs no mutation at all. The merged system wants both, with the boundary explicit: prose bodies cascade (rarely, post-collapse); computed fields re-price (always, free). The undercut verdict (§7.4) is the hinge.
3. **Fixed schema ergonomics vs derived-kind freedom.** ldoc's uniformity is why its tooling is simple; founding-question-derived kinds threaten a combinatorial config surface. The instances suggest the resolution: a small common core (identity, edges, trail, membrane — invariant) with kinds/dimensions as per-store declarations that only the *skills* and *validate rules* consume. The CLI stays dumb; the declarations stay data.
4. **Non-gating review vs silting.** Both estates chose non-gating for the same reason (gates that always defer become ladders that never fire), and both now observe the cost (unsigned residue; unreconciled drift). The shared answer is not gates but *clocks + decay + disposition* — open items must exert influence (nag at close, block only at genuine destinations like a release membrane), which is verisectorium's Disposition dimension and live_docs' missing trigger layer, one design.
5. **Who the store is for.** live_docs optimizes the agent-maintainer loop; verisectorium's organs VII–VIII insist the experiential interface (orientation, experiential reading, gold-lift) and the stewardship interface (the valve, decision briefs, the steward model) are load-bearing organs, not conveniences. A union adopts live_docs' mechanics without inheriting its silence on these two organs — the orientation gate (§6.7) is the first concrete piece.

## 9. The tooling-principles layer — what `arch/firmatum/principles/` would add to ldoc, and why it is a judgment upgrade, not an ergonomics one

*(Added 2026-08-29, same session, after a whole read of the principles corpus — itself another verisectorium: a carved `src/` of one-clause atoms over an influx gather, whose README adopts the udon-references seven-value decided-by vocabulary from the verisectorium template — the canon-praxes projection working across a fourth instance, down to confessing its own weak tiers: "anything carved in working sessions without a specific ask is `defacto` until traced (the original repo-file config atoms were exactly this, worn as `decided` until they collided with a decision already made)." Since this influx doc's readers will not necessarily have the principles corpus at hand, the load-bearing passages are quoted whole rather than referenced.)*

The steward's hypothesis prompting this section: the *judgment* of the agents running live_docs' skills might be enhanced by the right tooling principles applied to the ldoc layer — even though that layer has been stable. The principles corpus supplies the mechanism that makes the hypothesis precise. Its central formal claim, from `tools-are-observation-infrastructure`:

> "A tool's outputs are observations; the *ambiguity* of those observations is the one designer-controllable knob in a theorem-grade law bounding how much an agent's goals can distort its beliefs. Channel quality gates adaptation speed regardless of loop speed… 'Tool-interface quality' is therefore an existential quantity, not a throughput or ergonomics quantity."
>
> "κ measures how much the agent's *goals* are wired into how it processes what it sees (for an LLM, one forward pass does both, so κ ≈ 1 by construction and cannot be engineered away); A measures how much of an observation's meaning is left open to interpretation the agent's goals could bend. The product bounds how wrong wanting-something can make the agent's beliefs. Since κ is immovable, **A — a property of observation design — is the one knob anyone gets.**" — with the practical lever stated: "not reducing κ … but reducing A: more tests, more precise metrics, more structured outputs, less reliance on interpretive judgments."

Every skill verdict — cascade's four verdicts, dedup calls, level assignments, the pause gate — is formed over ldoc output. The knob on those judgments is the ambiguity of that output. That is the whole section in one sentence; the rest is where the knob turns.

### 9.0 Credit first — what ldoc already satisfies

Independently honored: stdout-is-data with diagnostics on stderr; no prompts ever (CONTRIBUTING: "fail loud, never prompt — agents and headless environments are first-class callers"); `--json` across read verbs; `--dry-run` on mutators; ambiguous-ref refusals that list the candidates (partial error-as-menu); `ldoc map` as a real glance organ with AGENTS.md mandating it first; and — substantially — **`--note` on mutating commands is intent-as-parameter, shipped**, with the session summary as the second intent level and the close-gate as enforcement. The principle's origin case (from `intent-as-parameter`, October 2025) is worth carrying because it is the exact failure class live_docs' membrane exists for:

> "The semantic intent had been 'add a citation to this quote, keep the numbering consistent, track progress'; the mechanical operations had been 'insert `[^tag]` at a text position and hope the document matches my mental model.' When an edit failed… the error was, in the author's words, a *phenomenological revelation*: the file had structure the agent hadn't comprehended, the mental model was stale, and the whole session had run at the wrong abstraction level — 'my intent was semantic, my tools were syntactic.'" And the anti-pattern warning that travels with it: "intent *comments* drift and lie… Prefer intent carried on *operations and events*, which are dated and immutable, over intent as decoration in the artifact" — which is precisely what ldoc's WAL-carried notes already do.

### 9.1 The store has no "look" — the glance duties are unserved (highest leverage)

`form-agentic-eyes` (the master design for agent-facing glance surfaces) assigns any glance surface two inseparable duties, in the steward's words:

> "*turn unknown-unknowns into unknowns* — mass, censuses, denial marks, so the reader's sense of what it has NOT seen is calibrated — *and show the place as a living, evolving system* — recency, heat, movement, so the glance answers 'where is this alive' in the same pass."

And the mode of use: "the glance is **perceptual, not interrogative**… *'look at the landscape before asking it a question'*… a question formed before looking is shaped by priors, and the landscape reshapes which questions exist."

`ldoc map` performs structure only — no recency, no anomaly channel, no aliveness. An agent orienting in a store cannot see, in one look: which signposts moved recently, that 29 DRIFT flags stand, that 22 reviews are unsigned, that 55 warnings share one class, which docs are hot. Each is a separate command the agent does not know to run — which is how the silting of §3.3 happened. An `ldoc map` (or `ldoc glance`) carrying recency order plus a one-line anomaly footer (drift / unsigned / warnings / pending counts) is aspectus-for-the-store: it makes the open queues *exert influence* — the Disposition failure of §8(4) fixed at the observation layer rather than the process layer. And the norm that would then bind has its enablement condition stated honestly in `norm-observation-is-the-default`:

> "the blanket is only enforceable when an instrument makes the default nearly free — *'the friction was never missing intelligence, it was a missing cheap instrument.'* A norm like this asserted *without* a cheap honest glance-instrument is exhortation; with one, it is an affordance."

Caveat carried from the same atom's priming carve: heat/recency are priming facts — a de-novo audit pass wants "*unprimed observation, not blindness*: shape facts (tree, censuses, mass, kinds) are auditor-safe; provenance-of-work facts (heat, age, recency order, deltas) carry exactly the signal a de-novo pass must not inherit." A store-glance wants the same cold preset.

Also applicable at the line level, from the same formulation's concern 9 (steward, after hitting unglossed numbers cold): "*Data without units or labels or context is just another area ripe for confabulation and misunderstanding — potentially correct, but when wrong it's wrong in the most dangerous way.*… An unlabeled number is a maximally ambiguous observation: the reader's priors fill the gap, the fill is phenomenologically indistinguishable from reading, and a wrong fill raises no error."

### 9.2 Move the 60%-shaped bookkeeping out of the judgment loop

`the-crystallized-process-thesis`, the corpus's oldest claim:

> "a tool is **crystallized process** — hard-won practice encoded so it no longer needs conscious recall — and most of what goes wrong in agent work is not a shortfall of intelligence but the absence of that crystallization. The quantified form is a **60/30/6/4 distribution**: in any real task, roughly 60% of the work is deterministic logic that should be pure code, 30% wants light intelligence…, 6% wants real reasoning, and 4% is genuinely judgment-critical. Tools exist to absorb the 60+30 so the mind in the loop spends itself on the 10 that needs it." (The numbers are marked `heuristic` in the source — "the distribution's *shape* — most friction is crystallizable — is better supported than its numbers.")

Read cascade-check through that lens: the skill has the agent hand-maintain a BFS queue, a visited-set, and a verdicts map — pure 60-shaped mechanics interleaved with the 4%-judgment (the verdicts themselves). Traversal errors pollute verdicts, and the mechanical load competes with exactly the deliberation the skill exists for. `ldoc blast-radius <ref> --json` — the reachable set over hard edges with each neighbor's status, frozen-flag, and last-change precomputed — leaves the agent *only* the verdicts. Same move for map-concepts-to-docs (a candidate-match verb) and the garden phases (a mechanical smells report — hot-file counts, wide requires-lists, compound titles — computed by ldoc, adjudicated by the agent). The behavioral mechanism, from the same essay's companion (`the-pattern`): "Not 'make incorrect things impossible' (too rigid) but 'make correct things so easy that incorrect things feel like friction'" — and its measured failure direction: "one agent's post-mortem records that chaining unverified edits 'was the easiest path' — and broke the system three times. When the gradient points the wrong way, agents slide down it."

### 9.3 Refusals as the law channel — teach at the violation moment

live_docs' deepest recurring cost is §3.2 #4's "the same feedback they give every agent on its first ldoc writes" — the laws live in AGENTS.md and skill files, which the reachability failure showed agents can skip. `errors-that-teach` names the alternative channel and why it is the right one:

> "Every tool interaction does up to three things at once: it *mutates state*…, *reveals state*…, and *teaches law* (shows what invariantly governs this tool's little jurisdiction — what it will and will not ever do). Errors are the interactions where the law component dominates, and that makes a refusal precious rather than merely unfortunate: it is the *safe* channel for an agent to learn a system's constraint surface. The alternatives are worse — learning a constraint destructively, or never learning it until it bites. …A good refusal **mutates nothing**…, **reveals state**…, and **teaches the law** that was violated — ideally as a menu of exact next actions."
>
> And the payoff line: "well-taught laws become infinite-velocity components of the agent's environment model — learned once, never re-derived." Plus the attention-economics answer to why refusal beats documentation: "Violation-driven learning is *attention-efficient* precisely because the lesson arrives exactly when it is relevant and load-bearing."

Concretely for ldoc: `new` with an answer-shaped label or a type-prefixed title warns *with the law* ("a label names the subject, not the conclusion"); `set --status target` surfaces the deferral test in one line; a level above `incidental` with no decided-by asks who decided. Every caught discipline from the §3 ledgers becomes a teaching refusal — cheaper than a hard mechanism *and* than prose, because it fires only on violation, exactly when it is load-bearing. The machine-mode shape is the same essay's proposed refusal contract: "Every tool error declares its three components as machine-readable fields…: `mutated:` (which must read `nothing` or itemize the exact changes), `observed:` (what matched, where, what exists), `law:` (which invariant was violated)" — with its own honesty note kept attached: "a machine-legible `mutated: nothing` that is *wrong*… is more dangerous than honest prose, because I will trust it more." Two supporting norms from the carved atoms, whole: `norm-refusal-names-class` — "'Not found,' 'not unique,' and 'resolves to several' are different situations with different repairs… The class is first-class language, not a flavor of a single 'error' string"; `norm-refusal-offers-next` — "Error-as-menu: offer candidates as ready-to-use exact next actions."

### 9.4 Laws queryable before violation

The same essay's dry-run generalization: "A dry-run channel: a tool answers 'would this call succeed?' without performing it — moving law-learning off the violation attempt entirely… Converts a mutating, state-changing probe into a pure… observation" (with its named tension kept: ask-first channels compete with finite attention and "may simply go unasked" — and TOCTOU: "a dry-run that diverges from the real call's behavior teaches a *false* law"). For ldoc: a batch `ldoc check` pre-flighting synthesize-doc-changes' whole write set — level collisions, label smells, status objections — *before* writing, at the moment the agent's judgment is still cheap to change. The suite's shape for it, from the headless gather: "A dry run that emitted the *structured would-do* — same schema as the real run's result, marked hypothetical — would give agents the predict-failure-before-execution affordance… as data rather than as reassurance."

### 9.5 `ldoc feedback` — the steward-decided suite norm, and the ledger loop mechanized

`norm-feedback-verb` (decided-by steward, 2026-08-28 — "*all of our tooling should allow for feedback/friction points to be reported using a verb on the tool on the cli itself*"):

> "A verb makes the true thing (reporting the friction now, in place, with context the tool can attach itself — version, cwd, the failing invocation) cheaper than the fabricated thing (carrying the annoyance silently, or paraphrasing it later from memory). The tool is present at the moment of friction; the report should be one command away. …append-only, provenanced (who/when/version/cwd), lands where the tool's maintainers already look… and never blocks."

For live_docs this closes the loop that currently runs through the maintainer's memory: agents hitting skill/tool mismatches file specimens mechanically, and the §3.1 ledger process gets its Failure sections pre-captured with provenance. It is also the crystallized-process essay's "crystallization-request channel" ("a standing file of tool-requests-from-lived-friction, so the tool suite grows from measured pain rather than from anticipation") — and the intent-vs-tool-mismatch telemetry the intent essay names: "when the stated intent was add-a-citation but the tool used was find-and-replace, that mismatch, logged, is a request for a better tool that nobody had to file."

### 9.6 Smaller but real

- **Exit vocabulary** (`form-exit-vocabulary`, whole): "`0` — success, including 'nothing to do' when that is success; `1` — failed check / would-change (md-press `--check` precedent); `2` — usage, or not-yet / refused-to-act-as-requested; `130` — SIGINT. Further codes only when an agent must branch without parsing stderr." `ldoc validate` distinguishing clean/warnings/errors by exit lets skills branch mechanically.
- **Help is the law channel** (`norm-help-is-law-channel`): "`--help` is the ex-ante half of the law channel: what the tool will and will not ever do, taught *before* the first refusal… Name the dangerous cases in the help itself." The golden rule (never hand-edit) and `rm --force` semantics belong *in* `ldoc help` — doubly so here, because live_docs' own constraint doc rules that agent-facing policy must live in skills or the CLI, the KB being invisible in consumer repos. Help is the CLI half of that ruling.
- **Omission-first validation** (`structured-output-two-mechanisms`): the measured finding — "small-model failures split roughly 68% *omission* (a required field simply absent) to 32% malformation… And when a required parameter is missing from what the caller gave, models tend to **fabricate a plausible value rather than ask**" — and its design consequence: "validators have the emphasis backwards: the first-class question is 'what's missing'… A checker whose primary output is a filled-in skeleton of absent required material would match the measured failure distribution." (The fabrication finding is also the deep reading of the register war: required-at-generation fields — labels, summaries — get filled with plausible fabrications; a structured way to leave them honestly pending, or to ask, is the evidence-backed counter.)
- **Perceived elapsed time** (`norm-elapsed-time-is-perceived`): "the TicToc benchmark finds LLM agents temporally blind to elapsed time — best alignment ~65% *even with timestamps in the prompt*"; the steward's scale law: "*once you're at 48h, a difference of another 5m feels inconsequential, but when you have been doing stuff in the realm of seconds, 5m can feel like 48h*" — so staleness surfaces (review ages, doc last-touched, drift-flag standing time) render perceptually (log-scale density, SIGNA-style), paired with a plain form, glyphs never in JSON.
- **Constrain by tool-set, not prose** (`tool-definition-anatomy`): "repeated across genuinely separate implementations, **read-only roles enforced by leaving tools out, not by prose**… this research programme learned it the hard way when an agent asked merely to *assess* which worktrees were safe to delete went ahead and removed all eight. The codified rule — constrain by tool-set, never by instructions — has two origins and one lesson: prose does not bound a capable agent; capability does." Skills that must not mutate (validate, assess-blast-radius, the read phases of garden) could run against a read-only ldoc mode — the wall-is-a-handle pattern, cheap in a CLI.

### 9.7 One boundary that cuts the other way

`norm-caller-tunes-the-channel` — "The observed may speak *into* the channel; only the caller tunes it… a place… never sets **channel parameters**: columns, budget, depth, format, quiet thresholds, or anything else that shapes how the observer sees" — grounded in the interaction-channel result: "an emitter that controls content fed into an agent's update can choose the *sign* of the update on load-bearing beliefs. 'The faster you learn, the faster you die.'"

This *blesses* live_docs' current `.live_docs.toml` (store identity and write-scope — the tree's to own, per the same carve that blesses `.md-pressignore`), but it flags two forward paths: WISH.md's "custom viewer options… custom css" should land caller-side, never repo-side; and the KB-content-instructs-agents pattern is safe only because the store *is* the instruction surface by design — a consumer store ingesting third-party material is the adversarial-content case, and nothing in ingest-reference currently guards against instruction-shaped content arriving through the membrane. One sentence in that skill before it is a scar.

### 9.8 The through-line

These are judgment upgrades, not conveniences, by a common mechanism: they move deterministic load out of the deliberation loop (9.2), cut observation ambiguity at the exact surfaces where verdicts are formed (9.1, 9.2), and relocate law-teaching from skippable prose to the violation moment, where attention is guaranteed (9.3, 9.4). That is the κ×A knob, the tempo law ("you cannot outrun a bad observation channel by iterating faster"), and attention-efficient law-learning, applied to a doc store's porcelain. §7.5's promote-disciplines-to-mechanism list is this section's little sibling; the principles corpus supplies the *theory of why* those promotions pay, and the quotes above are its portable core.
