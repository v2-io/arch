# axes — classification track beside Ghostty paint metrics

Parallel to the Ghostty raster / metrics work in the parent directory. This track does **not** rewrite `bmp-metrics*.tsv`, `.rasters/`, `corpus/`, `preview.html`, `measure-ghostty`, or `TRACKING.md`.

Join key with the paint TSVs: **`hex`** (`U+2460`) and **`cp`** (decimal). Packed raster path is the same convention the paint scripts already use: `.rasters/4x/packed/HH/HHHH.png`.

Unicode identity here is **Unicode 14.0.0**, same as `unicodedata` on this machine and `bmp-tables.md`.

## What this is for

Four classification axes, plus a PNG-shape axis that can disagree with Unicode theory:

| axis | question | primary outputs |
|---|---|---|
| (a) number systems | which BMP ranges are counting systems, and which of those are positional-decimal vs additive / hybrid / ciphered / unit-named / tally / fraction / presentation | `data/unicode-axes.tsv`, `data/number-systems.json` |
| (b) gradients | specific fill series (block elements) vs derived density (braille, stars, shades, PUA batteries) | `data/unicode-axes.tsv`, `data/gradients.json` |
| (c) font coverage | cmap of the Ghostty stack + extras in `fonts.toml`; preferred face vs alternatives; native vs patched vs pan-Unicode dump | `data/font-coverage.tsv`, `data/font-block-summary.tsv`, `data/font-lineage.json` |
| (d) tokenization | quantitative (tiktoken / llama / optional claude-approx) and qualitative (agent surveys) | `data/tokenization.tsv`, `data/token-survey.md` |
| (e) shape | ink-grid on **the other track's packed rasters** plus Unicode theory (braille bits, designed fill, name tags) plus Ghostty `packed_density` | `data/png-features.tsv`, `data/shape-axes.tsv`, `data/shape-agreement.json` |

The HTML (`index.html`, generated by `render-axes`) is an exploration dashboard that *reads* those files and *points at* the existing rasters. It is meant to be foldable into `render-corpus` later by joining on `hex`.

## Scripts

Run from `axes/` or via path; they locate this directory themselves.

```
./classify-unicode     # (a)(b)  UCD + curated overlays → unicode-axes.tsv
./measure-coverage     # (c)     fonts.toml + CoreText cmap → coverage TSVs
./analyze-png          # (e)     other track's packed PNGs → 16×16 + visual clusters
./enrich-shape         # (e)     join grid + Unicode theory + Ghostty packed_density
./measure-tokens       # (d)     tiktoken + local llama tokenizer → tokenization.tsv
./survey-tokens        # (d)     qualitative prompts / ollama samples
./render-axes          # HTML dashboard
```

`fonts.toml` is the editable font DB. Ghostty-used faces are inherited from `bmp-metrics-ghostty.tsv` when that file exists; extras listed in the toml are always measured. Adding a font is: put a `[[extra]]` with a CoreText family name (and optional path). Re-run `measure-coverage`.

## Honesty notes

- **UCD numeric ≠ “is a counting system.”** Hebrew, Greek, Armenian, Georgian, and Cyrillic letters are culturally used as ciphered numerals and have **no** `Numeric_Type` in Unicode 14. They are catalogued here as `ciphered-cultural` with `ucd_numeric=no`.
- **Nd 0–9 consecutive runs** are auto-detected as positional-decimal digit sets (Unicode’s own definition of decimal digits). Fullwidth digits are the same system under a compatibility presentation.
- **Suzhou/Hangzhou numerals** (U+3021–U+3029, U+3038–U+303A) are a positional decimal *in use* but are **not** `Nd` (encoding history). Tagged `positional-decimal-not-Nd`.
- **Grok’s tokenizer is unpublished.** `o200k_base` is a modern BPE proxy, not a claim about Grok. Claude is an unofficial approximation if the tokenizer files load; otherwise marked absent. Local ollama `/api/tokenize` is 404 on this ollama (0.32.x).
- **LastResort “covers” everything** and is treated as a hole-filler, not a real face.
- Nerd Font PUA glyphs are a **patch**, not native design of the predecessor family.

## Professio (this session)

The point of this track is to find out which Unicode ranges can actually carry number, density, and shape *as a channel* — to a terminal face, and to a language model — rather than guessing from block names. The paint-fidelity work next door answers “what Ghostty draws”; this answers “what the codepoint *is*, which font can say it, whether a model can read it, and whether the pixels form a family.” Under pressure the easy failure is to treat trained Unicode lore as UCD (it is not: gematria is real and silent in the database) and to declare tokenization “broken” from a token count without asking whether the glyph is still recognizable. I expect font coverage and PNG clustering to be the parts that stay honest if I keep them as measurements, and the cultural-numeral overlays to be the part I must keep labeled as overlay.
