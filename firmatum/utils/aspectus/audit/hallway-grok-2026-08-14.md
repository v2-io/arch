**What it is.** A one-shot picture of a filesystem place: timestamp, absolute path, then a tree with a hard line budget (default 80) and a depth cap (help says 2; Joseph’s user config silently makes it 3). Unexpanded directories keep a census instead of vanishing. Well-known junk — `.git`, `target/`, `__pycache__`, `.obsidian`, `.claude` — is “furniture”: folded onto the parent as `[kind: …]` and `[git: remote<…> br<main> @sha dirty<N>]` rather than listed as children. Recency-first, directories first, so a second look puts what moved at the top. Later builds add a heat score, per-file line counts, and a richer census grammar.

It is trying to be the thing I actually want from `ls`/`tree` when I land in an unfamiliar repo: not an enumeration, a *look*. That intention is the best thing about it.

**What I liked.** The git stanza is the first thing I trusted and the first thing I used. `dirty<4>` on memorata was exactly `git status --porcelain` (2 modified, 2 untracked). Remote is the useful host/path, not a URL. Submodule/worktree gitlinks (`gitdir: ../.git/modules/asf`) still produce a real git line on the repo itself, which is the fact I needed.
