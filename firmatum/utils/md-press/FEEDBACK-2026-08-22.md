## 1. Low-confidence join of house pseudo-display `$$…$$` lines (FORMAT-forbidding)

asf's FORMAT (`doc/sop/format.sop.md` §Math Formatting) requires display delimiters on their own lines: `$$...$$` "on their own lines, blank line before and after." A common house shape is a single-line display block between prose lines with no blank line around it. md-press joins those at p≈0.47 and says so on stderr, i.e. it knows it is unsure and joins anyway:

```
$ md-press - < 01-aat-core/src/der-tempo-composition.md | diff 01-aat-core/src/der-tempo-composition.md -
md-press: (stdin): wasn't sure about the following and JOINED the lines. ...
    (p=0.47) *[Derived (Super-additive witness, exact)]* Two sub-agents observing $… \n $$ \frac{\mathcal T_c}{\sum_i \mathcal T_i} = \frac{1}{1+\rho} \gt 1, …
    (p=0.47) $$\frac{\Delta\varepsilon^\ast \nu_c}{\lVert\delta_{\text{critical}}\r… \n The closure-defect increase (expressed as tempo penalty) exceeds the n…
    (p=0.40) - **Composite persistence condition.** The composite persists iff $\ma… \n $$\mathcal{T}_{\text{joint}} \;\gt\; \frac{\rho_{\text{ext}} + \vareps…
```

Result (lines 42–44 of that file): prose + `$$ … $$` + prose become one line, so the display block is now inline in a paragraph. The render-equality gate passes (CommonMark sees text either way), but GitHub/Obsidian render `$$` inline-in-paragraph differently from a standalone display line, and FORMAT treats it as a violation. Suggested direction: a whole-line `$$…$$` (single-line display block) is a preserved break in both directions, like the whole-line single-span `$…$` you already keep; and when a join is below ~0.5 on a line that *starts or ends* with `$$`, preferring not-joining would match the house convention. Ideally the repo convention ("display math on its own line") is a rule, not a probability.

## 2. GitHub math-compat checks lint-md ran that md-press does not

`bin/lint-md` (asf, Python) enforced a set of render-compat rules from FORMAT §Math Formatting that md-press does not check. Inventory, from its rule names as they fired over the asf tree today:

- `raw > in math — use \gt` / `raw < in math — use \lt` (GitHub reads `<`/`>` inside `$…$` as HTML and corrupts everything after).
- `bare | in math — use \vert, \lvert/\rvert, or \mid` (breaks inside table cells; ambiguous rendering).
- bare `*` inside inline `$…$` → `\ast` (markdown emphasis parser runs first).
- `inline math spans with emphasis-vulnerable _` — two or more `$…$` spans on one line with `_` after `}` get matched as italic delimiters across spans; fix is dropping optional braces (`$\hat P_\Sigma$` not `$\hat{P}_\Sigma$`), and `_` inside `\text{}` → `-`.
- `LaTeX command outside math: \text / \mid / \to / \frac / \sum …` and `bare math variable outside $: C_1, n_{...}` — LaTeX or math-shaped tokens in prose that should be inside `$…$` (this one overlaps `--math`'s job; the others are checks, not promotions).
- `$$ should have a blank line before/after it`.
- `#slug` inside math mode (LaTeX reads `#` as a macro-parameter token; FORMAT forbids slug-refs in math).

Most of these are deterministic and belong in `--check` as reported issues (exit 1 without writing), and several are safe auto-fixes (`\lt`/`\gt`, `\vert`, `\ast`, `_`→`-` in `\text{}`, `$$` blank lines). lint-md's own caveat is worth inheriting: its bare-Greek check skipped code spans, so backtick-wrapped Unicode math (`` `η → ϱ` ``) passed lint and rendered as monospace — md-press's parser-sited approach should be able to flag that case rather than skip it.

## 3. Usage note (not a bug)

Every asf tracker, `CHANGELOG.md`, and several segments fail `--check` at HEAD — pre-existing wrap debt from before md-press existed. The commit-time question asf now asks is "did this change add to it," by checking the HEAD version alongside the worktree version. A corpus-wide in-place press is queued behind item 1.
