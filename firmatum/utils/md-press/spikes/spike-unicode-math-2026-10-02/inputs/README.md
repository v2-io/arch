# Inputs carried in from the coordinating session (2026-10-02)

These were produced today by the agent that reworked md-press's math pass (the session described in `../../../STATUS.md` → *Math on by default, and what that required*). They are here so you don't have to regenerate them. They are measurements with known biases, and nothing about how to approach the spike.

- **`pieces.jsonl`**: every piece of text md-press's current math stage would send to a model, over the estate's tracked `.md` files outside `.moved*`, `_older`, `_ref` and `ruby-community`, excluding files under a `.md-pressignore`. One JSON object per piece: `{file, line, text}`, where `line` is the line number in md-press's *unwrapped* output, not the source file. 9,812 pieces, 8,027 distinct. A "piece" is what is left after md-press strips the markdown prefix (list/quote/heading markers, indentation), splits at prose-role `→ · × ≈ …`, and splits at sentence ends. **Bias:** these are only the pieces that today's trigger rule (`needs_math_pass` in `src/math.rs`) selects. Math with no Unicode trigger at all (ASCII `x_t`, `a^2` in prose) is not represented, and neither is anything the trigger rule wrongly calls prose.
- **`sample.json`**: 240 of those distinct pieces, seeded at random (120 with `/arch/asf/` in the path, 120 without).
- **`prop-llama.jsonl`, `prop-muse.jsonl`**: each model's raw proposal for each sample piece, with seconds per call. Both got the identical few-shot prompt (`../../../prompts/unicode-math.txt`) as a raw completion, temperature 0, stop at newline, length cap `64 + len/2` tokens. llama3.2:3b ran via ollama. Muse Glimmer 30B (k-quant GGUF + DFlash drafter, llama.cpp b10358) ran via `llama-server /completion`. The machine is an M4 Max with 48 GB.
- **`judged-llama.jsonl`, `judged-muse.jsonl`**: the same records after md-press's real gates (via `harness/judge.rs`): `outcome` ∈ converted / unchanged / refused, `reason`, and `result`, the text md-press would write. This uses today's gates, including `operands_survive`.
- **The coordinator's hand review of every accepted conversion** (from the first judging pass, before `operands_survive` existed). llama3.2 had 5 wrong-but-accepted: ids 94 (`ρ/R` → `\rho/\rho`), 105 (`||δ||` → `\delta`), 181 (`𝒜` → `\mathcal{S}`), 26 and 130 (a full stop swallowed). The new gate now refuses all five. Muse had 1 minor slip: id 102, `δ_sat^(1)` → `\delta_{\mathrm{sat}^{(1)}}`, a misplaced brace. Everything else accepted read as correct to me. That is one reader's judgment, unverified by a second.
- **`harness/`**: `pieces.rs` (collects pieces through md-press's fake-model seam, `Model::fake`) and `judge.rs` (runs any `{text, proposal}` JSONL through the real gates). Both were bins in a scratch crate whose `Cargo.toml` is here; it depends on md-press by path. `propose.py` and `analyze.py` are the collection and summary scripts.
