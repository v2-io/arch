# **NOTES:**
# *git-rel*      How it's represented or rather its relationship wrt git
#  `gitroot`:    Project directory is its own git root
#  `sub(*)`:     A submodule is a normal git root that is also a submodule of another repo. Subgit means tracked by git but a subdirectory within.
#  `group`:      A directory with a set of repos (e.g., all from one org) and usually some basic scripts. Like `no-git` but has cloned child git-repositories in subdirs.

# *git-vis*      Git visibility, with `private`, `public`, and `external` implying it has a remote.
#  `external`:   External usually implies `public`-- but could technically be a private repo where we are invited as a contributor or viewer etc.
#  `group`:      Groups may have repos w/ various visibility, but usually external.
#
# *lifecycle*
#  `nascent`:    Often little more than the core ideas and/or tiny proof of concept and/or originating spike etc.
#  `experiment`: In ther very loose sense of the word-- might be empirical (distinct from its paper), a theory, coding spike, attempt at proof-of-concept, toy idea, etc.
#  `pre-*`:      Active development toward a named milestone (poc / mvp / release); re-enterable — lifecycle is not a one-way ladder.
#  `ongoing`:    Unlike maintenance, it is expected to stay active without any particular "finished" objective (whereas maintenance has usually reached its primary objective).
#  `reference`:  Could definitely continue to influence things. paused+reference is a typical combination for internal projects that are resurrectable. (Usage itself is the local-use axis's business; paused already kind of implies not-in-use or it would be maintenance.)
#
# *activity*
#  `active`:     Aspires to regular active pushing toward some milestone.
#  `watch`:      Not being actively contributed to necessarily, but watching for changes, updates, requests, etc.
#
# *proj-rel*     Relationships with other projects. Alias for (`root` || `mid`) is `parent`
#  `root`:       A *root* is a project *with children* and but *no* parent project of its own.
#  `mid`:        A project *with children* and at least an immediate *parent*. Alias: `internal`
#  `leaf`:       No children of its own, but at least an immediate parent (which would be a `mid` or `root`
#  `isolated`:   An otherwise project root with no parent and no children.
#
# *public-use*  `preprint`, `submitted`, & `accepted` are especially intended for papers & books, although also datasets & related code.
#  `published`: Accepted and published for papers and books or preprint traction; public and discoverable via common sources (brew, cargo, etc.) if code.
#  `early`:     Innovators through early adopters adoption, or at least a few strangers with at least a nominal growth profile.
#  `broad`:     Late early-adopters through early-majority and beyond. Or, for papers, significant citations and discussions.
#
