# Stage-4 Unification — Brief

*To the unifying agent, arriving cold: you're joining at stage 4 of a five-stage effort (see `../RONR-12-MODEL.md` intro and `INTERFACE.md` header for the stage list). Stage 3 produced five independently-authored component models of RONR (12th ed.) parliamentary procedure, each internally coherent and following the shared external conventions in `INTERFACE.md`. These are the stage-3 authors' own final reports, condensed; the files themselves are the primary artifacts.

**`03-engine.md` (component 3 — pending-question stack machine).** Frame schema with the `applied_to`/`adheres_to` distinction (10:35); a business-context stack-of-stacks for interruptions that resume in place (marked `NOTE(judgment)` — RONR doesn't use nested-context vocabulary, but 13:7(2)/17:3(2) independence makes it the minimal faithful structure); `may-push` legality function with four declared guards (`no-question-pending`, `no-order-precluding`, `not-dilatory`, `not-same-question`); positional `effective_rank` handling Amend's rank modification (6:7) and Reconsider's making/consideration split (37:9); reverse-order unwind with the series-halting adoption table (10:34); bundle serialization distinguishing lossless (table, postpone) from lossy (commit drops postpone-indefinitely — 11:4, 13:19) with restore conditions. **`04-lifecycle.md` (component 4 — question lifecycle).** Four *parallel* statechart regions per question object: R1 disposition, R2 reconsiderability, R3 effect-in-force, R4 within-control-of-assembly. 14 states, ~25 transitions as fenced JSON with citations; three guards (`postpone-horizon`, `carryover-eligible`, `unrescindable`); six timers on the named temporal anchors (reconsider make/call-up windows, reconsider-enter-minutes, table-expiry, vote-challenge, renewal-unblock); explicit H* history semantics with three boundary-crossing erasures (day → debate rights; session → order exhaustion + same-question bars + renewal; referral → both intra-session). **`06-07-rules-scheduler.md` (components 6+7 — rule hierarchy + scheduler).** Component 6: rule classes; authority ordering plus four override rules a flat order can't express (specificity; the anti-delegation lock 2:16n5; content-not-name classification; precedent-as-persuasive); the eight interpretation principles (56:68) as tie-breaker predicates; suspension model split into per-class suspendibility/thresholds and seven absolutely-unsuspendable categories; change-threshold decision table per class; continuing-breach (null-and-void) grounds (23:6) exported as hooks for lifecycle/protocol; four exported guards. ## Known seams (surfaced by the authors themselves)

1. **Debate-order objects.** 03-engine declared `no-order-precluding` (it gates pushes) but believes the limit-debate/previous-question order *objects* belong under `rules:order/*` in 06. Decide ownership and rewire references.
2. **Order-exhaustion timers.** 06-07 references exhaustion of debate orders at session end but left the timers to 04-lifecycle. Confirm single ownership in the join.
3. **Threshold vocabulary extensions.** 01-catalog added thresholds beyond INTERFACE.md's list (e.g. `tie-or-majority-sustains-chair`, `two-thirds-neg` usage). Fold into one canonical threshold vocabulary.
4. **Event-vocabulary gaps.** 01-catalog notes no core `division-demanded`/`retake` events (it used its `result-window-open` guard instead); 05-protocol added eight namespaced events. Reconcile into one event vocabulary.

## The stage-4 task, as we understand it

Produce the unified model as structured data: one namespace, one motion registry (re-expanding 01's collapsed variants where that serves clarity), one guard registry, one event vocabulary, one threshold vocabulary — with every component's content preserved and every normative datum still carrying its §:¶ citation. `NOTE(judgment)` markers must survive unification (they are the honest-uncertainty layer, not noise). Duplicated rules across components (there will be some despite the ownership discipline) should be deduplicated *toward the owning component* with cross-references, not silently merged. The union of the named Form-and-Example test vectors is the acceptance suite; a verification pass (possibly by a separate agent) traces them through the unified model.

Structure the output so a stage-5 engine can be written against it — data files an engine loads, not prose an engineer re-transcribes.

If anything here fights the material as you find it, the material wins; note the divergence rather than forcing the join.
