## Known seams and open joins

1. **Debate-order objects and their timers.** The limit-debate / previous-question order objects are `rules:` state (adopted orders modifying governing rules for a scope); 03's `no-order-precluding` guard reads them; their exhaustion timers belong to 04. 15:18 / 16:11 is the shared spec all three must cite. Wire this ownership explicitly.
2. **The applicability table (the structural join).** SDC-1/SDC-2 admissibility knowledge is split across rank data, guards, per-record notes, and `catalog:table/appeal-yield-matrix` — with the remainder only in the book's SDC-2 prose. Extract an explicit per-motion `applies-to` / `does-not-yield-to` table; Chart I's right-hand "out of order when" column is the ready-made acceptance checklist.
3. **Guard registry.** Fold all guard declarations into a single positive-polarity registry per INTERFACE §5; 01 §5.5 is the seed (03 declares only `no-order-precluding`).
4. **Queue ids.** 03 references coarse queue ids (`scheduler:queue/general-orders`, `special-orders`) where 06-07 exports finer ones (`special-orders-unfinished`/`-current`, `general-orders-current`, `unfinished-business`). Pick one granularity (the finer set looks right) and rewire.
5. **Threshold vocabulary.** 01-catalog uses thresholds beyond INTERFACE.md's list (`tie-or-majority-sustains-chair`, `single-member-demand`, `chair-rules`, `not-voted`); all are sound and `not-voted` is genuinely needed. Fold into one canonical vocabulary.
6. **Event vocabulary.** No core `division-demanded`/`retake` events exist (01 expresses the window via its `result-window-open` guard; 05 added eight namespaced events). Reconcile into one event vocabulary, adding core events where the demand/retake exchanges warrant them.

## The stage-4 task, as we understand it

Produce the unified model as structured data: one namespace, one motion registry (re-expanding 01's collapsed variants where that serves clarity), one guard registry, one event vocabulary, one threshold vocabulary — with every component's content preserved and every normative datum still carrying its §:¶ citation. `NOTE(judgment)` markers must survive unification (they are the honest-uncertainty layer, not noise). Duplicated rules across components (there will be some despite the ownership discipline) should be deduplicated *toward the owning component* with cross-references, not silently merged. The union of the named Form-and-Example test vectors is the acceptance suite; a verification pass (possibly by a separate agent) traces them through the unified model. Three sweeps belong in that suite beyond the traces: (a) a Chart I right-column sweep — generate each secondary motion's out-of-order conditions from the unified model and diff against the chart; (b) a Table II sweep — re-expand the catalog's ~30 collapsed records to Table II's ~98 rows (the catalog's own `NOTE(judgment)` claims this is mechanical; treat that as a testable claim) and diff attribute-by-attribute; (c) [24:9–13] and [23:12–16] traced as *engine* vectors, not only protocol ones — they exercise the appeal-yield matrix, the least-redundantly-modeled region.

Structure the output so a stage-5 engine can be written against it — data files an engine loads, not prose an engineer re-transcribes.

If anything here fights the material as you find it, the material wins; note the divergence rather than forcing the join.
