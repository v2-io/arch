# Look: T1 well-formedness + the calibration gate, 2026-08-29

*Status: look, not a result. n=4 instrumented v3 runs (Qwen2.5-7B-Instruct, seeds 7 and 11 × screened/delayed_reuse). Full `g` lives only in `out/instr_*.json`; the slim copies in `data/` dropped it. Written before `/goal`, as the hour-shaped check Fable endorsed.*

## T1 arrays are well-formed

All four runs: `g` length 29 (= 28 layers + embedding), no NaN/Inf, no negatives. Four exact zeros, all at embedding (`g[0]`) on consecutive generated tokens `'1'` in both seed-7 variants (code `111`). That is `||embed("1")-embed("1")|| = 0`, not a capture bug.

Layer magnitudes increase monotonically (embed ~1, mid ~30–40, L28 ~265–274). A mean-over-layers `g` is almost just the last layer. EpiKV’s per-layer z-score is required, not optional.

`corr(step, mean_g) ≈ 0` at n_steps=54–56 — the positional-trend confound is not visible yet at this generation length. Causal rolling-64 cannot run: every trace is shorter than the window.

## The gate as written is not executable on captured T1

This is the thing that would have been expensive to discover mid-sweep.

`g[step]` is the L2 hidden-state change of the **generated token** (`[n_steps][29]`). Occlusion labels are over **prompt segments**. There is no per-segment axis on `g`. Spearman of “T1 rankings” against T3 span labels is undefined on what the spike stored.

That is also EpiKV’s actual object: they occlude windows of *generated* reasoning, not ingested context. Plan-NIAH’s 2×2 is the other object (ingested interiors / terminals / reuse lines). The captured signal and the gate’s comparison class are from different regimes.

Plan Phase 0 also listed KV key/value variance and next-token entropy/logprob as T1 suite. Per-step keys actually stored: `tok`, `seg_mass`, `ctx_mass_total`, `hh`, `g`. Rolling-z was never materialized (derivable when n_steps allows).

Two honest reinterpretations, not both the original gate:

1. **T1 as temporal/impulse** (what `g` actually is). Calibrate against *when* it fires — phase boundaries, reuse moment — not against which span occlusion breaks. Cheap on existing data. A first pass with inherited bands 7–13 minus 18–25 is noise at this n (as the plan warned not to inherit bands); not a verdict.
2. **T1 as span-ranking**, matching the gate’s Spearman/masking language. Requires **new capture** before scale: e.g. per-position KV variance aggregated to segments, and/or a prefill-side residual signal. Existing `g` cannot be retrofitted into a span ranking.

T2 *can* rank spans (`seg_mass[L][n_seg]`). Its gate is well-defined, with Fable’s authorial expectation: all-head T2 expected to collapse with length (confirmatory-publishable); supervised-head T2 is a live question and is not wired.

## Header split is analysis-level, confirmed on the four JSONs

Generator emits one segment per line; `"Room k is the {color} room."` is always the first interior span of that room (8 tokens here). Count line is always local index 2 *by construction* (header, one distractor, then count) — `analyze.py`’s `room_ints[2]` is currently safe; a generator `header` role should still tag the count line structurally (`reused_detail` already does).

Preview, all-head T2, n=4, Fragile-Truth family — **not a result**, a check that the relabel does work:

| ratio | range of per-run means |
|---|---|
| terminal / body | 7.0–7.9× |
| header / body | 2.8–3.0× |
| terminal / header | 2.4–2.6× |

FINDINGS’ 6.1–6.7× terminal/interior mixed headers into interior; splitting them out raises terminal/body, and headers sit in between. Directionally consistent with the occlusion landmark finding, still the pre-filter measurement.

Char-span→token double-counting (`a<e and b>s`) is in the rig as Fable said; not quantified here (tokenizer not on the python3 that ran this look). Worth measuring before any per-token normalization at 8–16 tokens/span.

## What I would want in a `/goal` before scale

- Generator: explicit `header` role (and keep `reused_detail`) before minting the larger set. Existing four runs: positional relabel only.
- Rig, before minting: decide T1’s object. If the gate stays “rankings vs occlusion spans,” add a per-segment T1 capture. If T1 stays the impulse scalar, rewrite the gate to a temporal test and keep `g`. Either way, add entropy/logprob (cheap) while the decode loop is open; rolling-z window = min(64, n_steps) until traces are long enough.
- Analysis: header vs body vs terminal; do not treat all-head T2 as the trunk signal; do not cite P2’s 0.35 vs 0.59; v2 decay numbers carry the failing-arithmetic confound.
- Then scale (both task shapes, position-varied placement, length toward 2K–8K, occlusion on the same instances). Muse stays resident on :8837 unless we need the 20GB.

Keep Muse warm was the call for this look (JSON-only; judge needed later).
