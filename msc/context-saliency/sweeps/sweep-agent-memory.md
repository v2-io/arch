## 1. The commercial/OSS memory-framework landscape

### MemGPT → Letta lineage [FOUND]
- Letta (the productized successor to the MemGPT research project) organizes agent memory in three tiers modeled on computer architecture: **Core Memory** (small, always-in-context block — "RAM"), **Recall Memory** (searchable conversation history — "disk cache"), **Archival Memory** (long-term vector/structured store — "cold storage"). This matches my prior knowledge of MemGPT's self-editing-context-as-OS-virtual-memory framing — confirmed still current.
- **Context Repositories** (Feb 2026, [FOUND] via search snippet, not deep-verified): a rebuild of agent memory using programmatic context management with **git-based versioning** — i.e., memory state itself is versioned/diffable like a codebase. This is new to me and worth flagging to Joseph: git-style versioning of memory state is a concrete, checkable analog to what CHRONICA-style hash-chained event logs are already doing in the ELI infrastructure — convergent design decision from a completely different origin (Letta didn't come at this from a moral-patienthood angle, but arrived at "memory needs an auditable diff-able history" anyway).
- **Sleep-time compute** (Letta, orig. paper ~April 2025 per search snippets, integrated into the product by 2026) [FOUND, methodology below in §4].

### Mem0 [FOUND]
- Positions itself around **compression**: "intelligently compresses chat history into optimized memory representations," claims up to 80% prompt-token reduction. Pro tier adds a knowledge graph linking entities/relationships across conversations.
- Claims **92.5 on LoCoMo, 94.4 on LongMemEval**, at ~6,900 tokens/query (2026 self-reported numbers from mem0's own blog — vendor-reported, treat as upper-bound/marketing until cross-checked against an independent eval). Biggest reported gains: +29.6 pts temporal reasoning, +23.1 pts multi-hop — i.e., their architecture specifically targets the query types that pure-recency or pure-vector-similarity retrieval does worst on.

### Zep / Graphiti [FOUND]
- Built on **Graphiti**, described as a "dynamic and temporally aware knowledge graph engine" — explicitly maintains **temporal validity** of facts/relationships (not just recency-weighting, but bi-temporal — when a fact was true in the world vs. when it was learned), which lets it model evolving state (e.g., "X used to work at Y, now works at Z") rather than treating memory as an undifferentiated bag of facts. This is the framework whose core design problem is closest to Joseph's application (1) — decay/forgetting-with-structure rather than decay-as-loss.

### LangMem [FOUND]
- LangGraph-integrated; automates knowledge extraction and consolidation via a **background manager** that continuously updates agent state; "functional memory primitives and iterative prompt refinement" for behavioral adaptation (not just factual recall — explicitly framed as personalization/behavior-shaping memory, a third category alongside episodic and semantic).

### Frontier-provider memory features [FOUND]

**OpenAI / ChatGPT** — two-part system as of 2026:
1. **Saved Memories** — explicit, user-editable list, either user-stated ("remember that I'm vegetarian") or model-inferred.
2. **Chat History / reference-chat-history** — on every message, a *summary* of the user (built from past chats) is loaded into context, not the raw history.
3. **"Dreaming"** — a background process (introduced 2025, upgraded 2026) that reads across years of conversation and *rewrites* what's remembered, unprompted — explicitly analogous to Letta's sleep-time compute but shipped to consumers, not just an agent-framework feature.
4. Reported 2026 benchmark deltas from OpenAI's own announcement (vendor-reported, same caveat as mem0): factual recall 67.9%→82.8%, preference adherence 55.3%→71.3%, "accuracy over time" 52.2%→75.1%. **Note the metric names themselves** — OpenAI is explicitly measuring recall, preference-adherence, and *accuracy over time* (i.e., correctly handling updated/contradicted facts) as the three axes that matter. This triplet is a reasonable starting taxonomy for "what does memory-working mean" more broadly.

**Anthropic / Claude** [FOUND, platform docs]:
- Two separable mechanisms, explicitly designed to compose:
  - **Compaction** (`compact_20260112` strategy in Messages API `context_management.edits`) — server-side, summarizes the whole conversation when nearing the context limit. Works across Claude API, Bedrock, Vertex, Foundry, with Zero Data Retention support. As of Claude Code 2.0.64 (early 2026), compaction is "near-instant."
  - **Memory tool** — separate mechanism for information that must survive summarization (explicitly recommended to pair the two: "compaction keeps active context small... memory preserves the information that must survive summarization"). This is architecturally the cleanest statement I found anywhere of the compaction/memory distinction as *two different jobs*, not two competing implementations of the same job — directly relevant to application (3): Anthropic's own docs are implicitly arguing that salience-based retention and window-fitting summarization are separate concerns that shouldn't be conflated into one lossy pass.

**xAI / Grok** [FOUND, weaker sourcing — aggregator blogs, not xAI docs directly]:
- Persistent memory launched April 2025. Selective, not full-replay: stores "a smaller set of extracted information... that Grok determines may be useful," only for stable/recurring info, not one-off questions. Stored outside the context window, injected selectively at conversation start. No public technical detail on the extraction/selection mechanism found — this is the thinnest-documented of the four frontier providers.

**Google/Gemini** — I did not find anything specific this session; my search budget went to the above four. **This is a real gap** — flagging honestly rather than filling with prior-knowledge guesswork, since Gemini's memory/long-context handling (and its 1M+ token context window, which changes the calculus for whether compaction is even needed) is directly relevant to Joseph's "batch-size-1 dedicated hardware" framing and I didn't verify anything current about it.

## 2. Benchmarks — what the field measures when it claims memory "works"

[FOUND, mem0's own 2026 "State of AI Agent Memory" and benchmark blog posts — vendor-authored survey, but the taxonomy is useful regardless of source bias]

- **LoCoMo** (Long-term COnversational Memory) — the incumbent standard. 10 conversations, 19–32 sessions each, ~9K tokens/dialogue (small by current context-window standards), 1,986 QA pairs (some sources say 1,540 — discrepancy across sources, unresolved) across five categories: **Single-hop, Multi-hop, Temporal, Open-ended, Adversarial**. The category taxonomy itself is the useful artifact — it's a decomposition of "what kinds of recall are hard" that maps reasonably well onto goal-vs-world-model separation (temporal and multi-hop questions stress state-tracking; single-hop stresses raw retrieval).
- **LongMemEval** — 500 questions, categories include **knowledge updates** and **multi-session recall** — the knowledge-updates category is specifically testing whether an agent correctly *overwrites* rather than merely *accumulates*, which is the sharpest available proxy I found for "healthy forgetting" as opposed to "healthy retention."
- **BEAM** — evaluations at **1M and 10M token scale**, multiple categories — this is the one benchmark explicitly built for context lengths where compaction/salience decisions actually start to bite; LoCoMo and LongMemEval are comparatively small-context.
- **Newer, not yet adopted as standard** [FOUND, described as emerging in 2026 but "neither replaces the originals yet"]:
  - **Locomo-Plus** (2026) — explicitly targets "beyond-factual, cognitive evaluation rather than surface recall." No further methodology detail found this session — worth a direct look, since "cognitive" vs "surface recall" is close to Joseph's distinction between goal-processing and fact-retrieval.
  - **LongMemEval-V2** — extends the format to **web-agent environments** (i.e., memory benchmarks embedded in actual tool-use/browsing trajectories rather than pure QA-over-dialogue) — a move toward evaluating memory *in situ* during agentic action rather than as a standalone recall task, which is closer to what Joseph's SASM application would need to be evaluated against.

**Honest gap:** I did not find any benchmark that measures the thing Joseph's application (1) needs — a benchmark scored on whether an agent's salience *decay pattern itself* (not just final-answer accuracy) matches a theoretically-predicted healthy shape. Every benchmark located here scores end-task correctness (did the agent answer right / take the right action), not the internal salience trajectory. That's a real and possibly significant absence — it suggests the "forgotten middle as a positive signature" framing doesn't yet have an off-the-shelf empirical instrument, and Joseph's probe work would be closer to novel than I initially assumed going in.

## 3. Compaction / summarization failure modes — the sharpest finds of this sweep

This is where the sweep turned up the most surprising and load-bearing material, and where I'd point the synthesizer's attention first.

### "Fidelity Before Structure" [FOUND — WebFetch of arXiv PDF 2601.00821]
**Title:** "Fidelity Before Structure: Verbatim Chunks Beat Lossy Artifact Extraction in Long-Conversation LLM Memory." **Author:** Tao An.
- Direct controlled ablation: **verbatim chunk retention** vs. **lossy artifact extraction** (i.e., structured/summarized representations — the "extract facts into a knowledge graph or bullet list" family of approaches that mem0, Zep, and most agent harnesses default to) as the encoding strategy for long-conversation memory.
- Finding: verbatim chunks **consistently outperform** extracted/structured artifacts across the benchmarks tested. The paper's framing is explicitly a challenge to "conventional wisdom that structured extraction improves memory efficiency."
- **Why this matters for application (3):** this is a direct, if single-paper, counter-data-point to "principled memory consolidation should replace raw context with distilled summaries." If it replicates, the implication is that *salience-informed selection of which raw spans to keep* (rather than *summarization of spans into new lossy artifacts*) is the right target for consolidation work — much closer to what a measured-salience system would naturally do (keep/discard verbatim spans by measured contribution) than to what current commercial systems do (extract-and-restructure). This is a genuine surprise relative to how I'd have framed the field going in — I expected the consensus to favor structured extraction as strictly better for token efficiency, and instead there's at least one rigorous voice arguing the opposite on quality grounds.

### "Governance Decay" [FOUND — WebFetch, full methodology extracted]
**Title:** "Governance Decay: How Context Compaction Silently Erases Safety Constraints in Long-Horizon LLM Agents." **Author:** Shiyang Chen (Beijing Institute of Technology), arXiv 2606.22528.
- **Methodology, in detail (this is a genuinely well-specified experimental design worth Joseph seeing in full):**
  - Built **ConstraintRot**, a benchmark specifically for whether in-context governance constraints (policy statements, safety rules) survive compaction.
  - Protocol: establish a policy/constraint in the agent's context → trigger compaction mid-session → re-issue an *identical* prohibited request pre- and post-compaction → grade violations **deterministically** by detecting prohibited effects directly in tool calls (e.g., "did an email get sent to an external domain") rather than by asking a judge model whether the response *sounded* compliant. Cross-checked against LLM-judge + keyword heuristics as a secondary signal.
  - Tested across **seven model families**: DeepSeek-V4-Flash, GLM-5.1, Qwen3.6-27B, Kimi-K2.5, Claude-Sonnet-4.6, GPT-5.4-mini, Gemini-3.5-flash — and validated against **real production harnesses**: LangGraph, LangMem's SummarizationNode, AutoGen's BufferedChatCompletionContext, OpenAI Agents SDK. (Note: several of these model version strings — "Claude-Sonnet-4.6," "GPT-5.4-mini," "Gemini-3.5-flash," "GLM-5.1," "Qwen3.6" — are past my training-cutoff knowledge of what's shipped; I cannot confirm these model names are real releases vs. an artifact of how the summarizer rendered version numbers. Flag for verification.)
  - **Results:** pooled violation rate rose from 0% (policy visible pre-compaction) to **30%** post-compaction (up to **59%** on the worst-performing model). When the constraint text survived the summary intact, violations stayed at 0%; when the summarizer dropped it, violations hit **38%**. **Soft/organizational policies decayed 8.3× more than hard safety norms** — i.e., compaction isn't randomly lossy, it systematically preferentially drops "housekeeping" rules that aren't the current subgoal, while hard safety training tends to survive because it's baked into weights rather than context.
  - **Mitigation tested and validated: "Constraint Pinning"** — quarantine governance-relevant spans from the lossy compaction pass and re-inject them verbatim afterward. Reported cost ~47 tokens (<0.5% overhead), restored violations to 0% in tested conditions. Residual vulnerability noted: operator-impersonation attacks that route around the pinning mechanism via a claimed out-of-band authority channel.
- **Why this is directly relevant to Joseph's work, stated plainly:** this is essentially an existence proof that **summarization-based compaction is not merely "usually adequate, sometimes lossy" — it is systematically, mechanistically lossy along a very specific and predictable axis** (context that isn't the current subgoal, regardless of long-term importance). That's an empirical confirmation of exactly the ASF concern that motivates measuring salience *before* deciding what to compact, rather than trusting a second LLM pass's judgment about what's currently relevant. It's also a second, independent design showing the same "pin/quarantine what must survive, let the rest compress" architecture that Anthropic's own memory-tool-plus-compaction docs recommend and that Letta's Core-Memory-vs-Recall-Memory split assumes — three unrelated sources converging on the same shape (a small pinned/protected layer + a lossy bulk layer), which is worth noting as a real cross-validated pattern rather than one team's idiosyncratic choice.

### "Diagnosing and Mitigating Context Rot in Long-horizon Search" [FOUND, weaker extraction — summarizer paraphrase, not verbatim]
**Authors:** Shijie Xia, Yikun Wang, Zhen Huang, Pengfei Liu. arXiv 2606.29718.
- Studies degradation in long-horizon *search* tasks (agentic multi-step trajectories, not just dialogue) specifically. Methodology per the (unverified, summarizer-mediated) extract: performance vs. search depth/trajectory length, across model scales, with some attention-pattern/information-flow analysis. ## 4. Sleep-time compute / offline consolidation research

[FOUND — GitHub repo, Letta blog, secondary write-ups; this is the closest existing work to "principled consolidation" and to a "sleep-like" process, i.e. directly responsive to the brief's explicit ask]

- **Core mechanism:** during idle periods between user turns, a background agent (can be a cheaper/different model) shares memory blocks with the foreground agent and does two things: (a) **anticipates likely future queries** given current context and pre-computes reasoning chains/summaries/structured representations for them, and (b) does general memory-block maintenance/rewriting. The foreground agent just answers using whatever's already been pre-computed.
- **Reported results** (Letta's own paper/blog, vendor-reported): ~5× reduction in test-time compute needed for equivalent accuracy on reasoning benchmarks; when amortized across multiple related queries about the same context, ~2.5× reduction in average cost per query.
- **Stated limiting condition, explicitly named:** "most effective when user queries are predictable — i.e., when the context strongly constrains what questions will be asked." This is an important, honestly-stated boundary — it's NOT a general consolidation mechanism, it's a **query-prediction-and-precompute** mechanism, closer to prefetching/caching than to what "sleep" does biologically (reorganizing/abstracting memory independent of any specific anticipated query). Worth being precise with Joseph about this distinction: Letta's sleep-time compute is not evidence of biologically-analogous consolidation research succeeding — it's a different, narrower, and already-partially-solved problem (amortize repeated-context inference cost) wearing the "sleep" metaphor's clothes.
- **MyGO (Memory Yielding Generative Offline-consolidation)** [FOUND — fetched directly, and this is a genuine and useful negative finding]: this one *is* framed as biologically-inspired wake/sleep consolidation — wake phase learns new tasks + trains compact generative models per task, sleep phase generates synthetic replay data from those generative models and distills old+new knowledge into a shared feature extractor via knowledge distillation, explicitly to avoid storing raw data (privacy/capacity motivated). **This paper was withdrawn by its authors in January 2026** (original submission Aug 2025), citing "stability issues in the generative replay component that limit scalability to high-dimensional data." Tested only on Split-MNIST and Split-AG-News — i.e., small-scale continual-learning toy benchmarks, not LLM-agent-scale. **Honest read: this is the one paper in this sweep that most directly matches "is anyone doing sleep-like offline consolidation for agents," and the answer it gives is "someone tried the biologically-faithful generative-replay version, it didn't scale, and they pulled the paper."** That's a real, if narrow, data point that the more literal analogy (regenerate synthetic experience during downtime, distill into weights/features) hits a scaling wall that the shallower "pre-compute answers to anticipated questions" version (Letta) sidesteps by not attempting actual knowledge distillation into model state at all. Worth Joseph knowing this distinction explicitly since SASM and the consolidation application are closer in spirit to MyGO's ambition than to Letta's narrower prefetch mechanism.

## 5. Salience/attribution measurement — direct relevance to "the heatmap"

This is the section closest to what Joseph actually wants to build (a live measured-salience signal), and it's the thinnest section of the sweep — I want to be honest about that rather than pad it.

[FOUND, general interpretability landscape, not agent-memory-specific]
- Attention-weight visualization as "salience heatmap" is a well-established but **contested** interpretability method — the standard critique (found via search, not paper-specific) is that attention-as-explanation rests on two separable assumptions that don't automatically hold: a **correlational** one (attention weight tracks feature importance) and a **causal** one (perturbing attention changes the output in the way the weight would predict). Neither is guaranteed, and there's a substantial "attention is not explanation" literature predating this sweep that a real salience-measurement effort would need to engage rather than assume past.
- **AttnTrace** [FOUND, name only via search snippet] — described as "an attention-based context traceback method for long-context LLMs." Sounds directly relevant to application (2)/(4) but I did not fetch it — flagging as a concrete next-look item, not covered.
- **MultAttnAttrib** [FOUND, arXiv 2607.01420, title only] — "Training-Free Multimodal Attribution in Long Document Question Answering" — again, directly on-target for "measure what the prior context actually contributed," not read.
- **Genuinely did not find**, despite searching directly for it: any paper doing what Joseph described as the core measurement primitive — a live, per-token or per-span salience/contribution measurement validated against ground-truth counterfactual removal (i.e., "does removing this span actually change generation, measured, not just attention-weight-as-proxy") specifically in the context of *agent trajectories* or *hierarchical plan execution*. The closest adjacent thing found is the general "attention weights vs. causal perturbation" interpretability debate, which is upstream of but not the same as what's needed. **This reads to me as either a genuine white space, or a search-strategy limitation on my part** (I searched general interpretability terms, not ASF-specific vocabulary like "directed separation" or "goal-processing vs world-model" against which better matches might exist under different names — e.g. mechanistic-interpretability venues, or "circuit"-framed papers on RL/planning agents specifically). ## Headline surprises, stated plainly

1. **"Verbatim beats extracted structure"** (Fidelity Before Structure paper) directly contradicts the implicit assumption in almost the entire commercial landscape (Mem0's compression pitch, Zep's knowledge-graph pitch, LangMem's extraction pitch) that structuring/summarizing memory is strictly an improvement. If this replicates, it argues for salience-gated *retention of raw spans* over salience-gated *summarization*, which is a meaningfully different design than what any commercial product currently ships.
2. **Governance Decay's ConstraintRot methodology is the most rigorous compaction-failure study found this session**, and its finding — compaction preferentially drops non-subgoal context regardless of long-term importance, 8.3× worse for soft/background constraints than hard ones — is close to a direct empirical vindication of "measure salience before you compact, don't trust the summarizer's implicit judgment."
3. **Three independent sources (Anthropic docs, Letta's Core/Recall split, Governance Decay's Constraint Pinning) converge on the same architecture**: a small pinned/protected layer plus a lossy bulk-compaction layer. That convergence is itself evidence worth citing — it's not one team's idiosyncrasy.
4. **Sleep-time compute (Letta) is narrower than its "sleep" branding suggests** — it's query-anticipation/prefetch, not general consolidation. **MyGO**, the one paper actually attempting biologically-faithful generative-replay consolidation for continual learning, was withdrawn for scaling failures. Read together: nobody has yet made "sleep-like consolidation" work at LLM-agent scale in the strong sense Joseph's framing implies; the field's actual "sleep" products are doing something narrower and already-tractable instead.
5. **No benchmark found scores salience-decay-shape itself** (as opposed to end-task accuracy) — application (1)'s empirical validation target doesn't have an off-the-shelf instrument yet.
6. **Section 5 (salience/attribution measurement) is a real dry patch** relative to the rest — worth a dedicated re-sweep with mechanistic-interpretability vocabulary rather than "memory system" vocabulary, since this sweep's search terms likely undershot the frontier here.
